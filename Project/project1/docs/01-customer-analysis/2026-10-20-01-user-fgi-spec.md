# ONEPIECE User FGI 정리 명세

- 버전: v1.1 — 인터뷰 후속 확인 반영
- 정리일: 2026-10-20, Asia/Seoul
- 목적: 고객 인터뷰 2회를 통해 발전한 서비스 가설을 보존하고, 구현할 UI와 후속 검증을 연결한다.
- 상태: 후속 확인을 반영한 최종 정리 명세. 고객의 평소 커머스 이용 경험, 인터뷰 이후 설계 결정, 후속 검증 계획을 구분한다.

## 1. 프로젝트 목적과 조사 질문

ONEPIECE는 브랜드를 인지한 20~30대 패션 중·고관여자가 상품을 충분히 탐색하고, 구매를 결정한 뒤 편리하게 결제 완료에 도달하는 자사몰을 구현한다. 두 차례 고객 인터뷰에서 얻은 단서를 UI에 반영하고, A/B 비교를 통해 구매 여정의 불편이 줄어드는지 확인한다.

두 인터뷰는 특정 자사몰의 사용성 평가에 한정하지 않고, 고객이 평소 커머스를 탐색하고 구매하는 여정에 초점을 두고 진행했다. 아래 항목은 그 내용을 정리하기 위한 분석 질문이며, 실제 질문지를 복원한 것은 아니다.

1. 고객은 어떤 목적과 브랜드 인지 상태에서 커머스에 방문하는가?
2. 상품을 탐색하고 구매를 결정할 때 필요한 정보와 조작은 무엇인가?
3. 구매를 결정한 뒤 장바구니·로그인·결제로 이동할 때 어떤 불편이 있는가?

인터뷰는 가설과 설계 근거를 만드는 단계다. 현재 확보한 두 사례만으로 타깃 전체의 행동이나 전환율 개선 효과가 검증된 것은 아니다.

## 3. 고객 1 — 브랜드를 깊게 탐색한 뒤 구매하는 고객

### 고객 설명

인터뷰 회상 요약에 따르면, 고객은 브랜드를 이미 알고 있으며 상품을 구매하려는 목적을 가지고 자사몰에 진입한다. 웹에서 상품을 충분히 깊게 살펴보고 원하는 상품을 장바구니에 담은 뒤, **동일한 자사몰의 앱 버전을 열어 장바구니에서 checkout으로 이동**하는 평소 구매 여정을 설명했다.

인터뷰 후 팀은 SAN SAN GEAR를 참고한 **3·4·6 그리드 선택을 탐색 UI 방향으로 확정**했다. 이 결정의 시점은 고객 1 인터뷰 이후다. 그리드가 구매 전환을 개선했다는 실험 결과는 아직 없다.

고객이 설명한 여정: 브랜드 인지·구매 목적 → 웹에서 깊이 탐색 → 장바구니 담기 → 동일 자사몰 앱 실행 → 장바구니 열기 → checkout 이동.

### 팀 해석

이 사례는 구매 목적이 있어도 상품과 브랜드를 충분히 탐색하는 과정이 필요할 수 있다는 단서다. 탐색 시간이 길다는 이유만으로 불편이나 이탈로 판단하기 어렵다. 구매 결정 이후의 반복 입력이나 이동 부담을 별도로 살펴볼 필요가 있다.

### 설계 방향과 확인할 내용

- 상품 목록·상세에서 구매 결정에 필요한 탐색을 지원한다.
- 선택한 상품·옵션·수량이 장바구니와 주문 단계에서 일관되게 이어지도록 한다.
- 3·4·6 그리드로 탐색 방식을 선택하는 방향을 B안에 연결한다.
- 웹 탐색과 동일 자사몰 앱의 장바구니·checkout을 이어 사용하는 맥락을 기록한다. 계정·기기·동기화 방식은 인터뷰 답변만으로 단정하지 않는다.
- 후속 검증의 완료 지점은 테스트 결제 승인과 주문 저장으로 정의한다. 기존 회상의 ‘구매 확정’은 배송 후 구매확정 기능의 요구로 해석하지 않는다.

이 여정은 고객의 기존 이용 경험이다. ONEPIECE 네이티브 앱 신규 개발, 웹·앱 동기화, 딥링크를 이번 구현 범위에 추가하는 결정은 아니다.

## 4. 고객 2 — 원하는 방식으로 후보를 좁혀가는 고객

### 고객 설명 및 인터뷰 후 발전한 방향

고객은 살 품목이 있을 때 커머스에 들어가 검색하고, 판매량순 등을 활용해 후보를 비교한다고 설명했다. 리뷰에는 이벤트 등으로 인한 편향이 있을 수 있다고 보아 판매량을 우선 참고하며, 원하는 상품을 선택해 구매하면 추가 탐색을 끝내는 경향을 설명했다.

이 인터뷰는 고객 1 이후 확정한 그리드 방향에 더해, **상품 후보를 좁히는 정렬·필터를 검토하는 근거**가 되었다. 판매량순은 고객의 기존 이용 기준으로 확인했지만 ONEPIECE의 최종 정렬·필터 기준은 아직 정하지 않았다.

### 팀 해석

화면에 보이는 상품 수와 이미지 크기를 조절하는 기능은 탐색 방식을 선택하게 한다. 정렬·필터는 후보 상품을 좁히거나 비교 순서를 바꾸는 기능이다. 두 기능은 역할이 다르므로 각각 어떤 문제를 해결하는지 확인해야 한다.

### 설계 방향과 확인할 내용

- 고객 1 이후 확정한 그리드 방향은 유지하고, 고객 2의 목적 구매와 후보 비교를 지원할 기능을 별도로 검토한다.
- 검토 후보: 판매량순 등 정렬 또는 조건별 필터. 최종 기준과 데이터는 미정이다.
- 판매량순·최신순은 표시 순서를 바꾸는 ‘정렬’, 사이즈·가격 범위 등으로 상품을 제외하는 것은 ‘필터’로 구분한다.
- ‘유용할 것 같다’는 의견과 실제로 상품 선택이 빨라졌다는 관찰 결과를 구분한다.

판매 데이터가 없다면 판매량순 기능을 실제 인기 근거가 있는 기능으로 표시하지 않는다. 임의 순위나 테스트 데이터는 효과 검증 근거로 사용하지 않는다.

### 통합 가설

**브랜드를 인지한 20~30대 패션 중·고관여자에게 충분한 상품 탐색과 선택을 지원하고, 구매 결정 이후 장바구니·로그인·결제의 불필요한 조작을 줄이면, 기존 UI보다 구매 과업 완료율이 높아지고 구매 단계의 이탈과 조작 부담이 줄어들 것이다.**

‘압도적으로 감소한다’는 효과 크기는 현재 근거로 확정하지 않는다. 탐색 시간, 결제 시간, 경유 화면 수와 실제 조작 수를 나누어 비교한다.

## 6. 구현 및 실험 범위

| 항목 | 현재 위치 | 확인 기준 |
| --- | --- | --- |
| 상품 목록·상세 탐색 | 핵심 서비스 범위 | 상품·옵션·가격을 확인하고 선택할 수 있는가 |
| 3·4·6 그리드 | 고객 1 인터뷰 후 확정한 탐색 UI 방향, B안 반영 | 전환해도 상품·카테고리 조건이 유지되고, 보기 방식 선택이 가능한가 |
| 장바구니→로그인→주문·결제 | 구매 여정의 검증 범위 | 선택 내용 유지, 로그인 복귀, 정상·실패 흐름과 중복 주문 방지가 동작하는가 |
| 정렬·필터 | 기준 선정 전의 후속 후보 | 실제 고객의 선택 기준과 사용 가능한 데이터가 있는가 |
| 동일 자사몰 웹·앱 이용 | 고객 1의 기존 경험으로 확인. 신규 앱 구현 범위는 확정하지 않음 | 고객 경험과 이번 웹 서비스 구현 범위를 구분했는가 |

상품 구성은 유지한다. FGI 정리를 근거로 새로운 추천·쿠폰·회원 등급 기능을 추가하지 않는다. 구매 시 로그인 필수라는 서비스 정책과 고객이 설명한 웹·앱 이용 여정은 별도로 기록한다.

## 7. 후속 A/B 검증 명세

### 비교 목적과 조건

브랜드를 인지한 실제 타깃 사용자가 같은 구매 과업을 수행할 때, B안이 A안보다 상품 선택과 결제 완료를 편리하게 만드는지 확인한다.

- A안: 팀이 확정하고 버전을 고정한 기준 UI. SAN SAN GEAR 참고 구현의 실제 상태를 확인한 뒤 기준으로 삼는다.
- B안: 같은 상품·가격·재고·로그인·결제 조건에서 합의한 UI 변경만 적용한다.
- 1차 비교 권장: A/B의 실제 차이를 먼저 확정한다. 그리드가 공통 적용되어 있다면 기준 기능으로 두며, 정렬·필터 등 합의된 차이를 비교한다. 그리드 자체의 효과를 확인하려면 그리드 선택 유무만 다른 별도 비교를 설계한다.
- 여러 기능을 한 번에 바꾸면 B안 전체의 차이는 볼 수 있지만, 어느 기능이 효과를 냈는지는 분리해 주장하지 않는다.
- 참여자는 A/B 중 한 버전에 무작위 배정하고 동일한 과업을 제시한다. 같은 사람이 두 버전을 쓰는 사용성 비교라면 순서를 교차 배치하고 학습 효과를 함께 기록한다.
- 표본 수·진행 기간·최소 개선 기준은 실행 전 팀이 정한다. 현재 숫자나 목표 효과를 임의로 확정하지 않는다.

### 공통 과업

‘이미 알고 있는 브랜드에서 원하는 상품을 탐색하고, 옵션을 선택해 장바구니에 담은 뒤 로그인하여 테스트 결제를 완료한다.’

그리드나 정렬 사용을 지시하지 않고 자발적 사용 여부와 이유를 기록한다. 자유 탐색 구간과 주문·결제 구간을 나누어, 충분히 탐색한 시간을 불편으로 잘못 해석하지 않도록 한다.

| 지표 | 정의 및 해석 |

| 조작·오류·복구 | 경유 화면 수, 입력·클릭 수, 로그인 재시도, 결제 실패, 선택 정보 유실, 중복 주문을 구분해 기록한다. |
| 선택 이유와 체감 편의 | 과업 직후 같은 질문으로 비교한다. 그리드 사용 횟수만으로 유용성을 단정하지 않는다. |

구매 버튼 클릭은 구매 성공이 아니다. 테스트 결제 결과는 실제 매출·실구매 성과로 표현하지 않는다. AI 페르소나 실행은 경로·오류·이벤트 수집을 점검하는 기술 검증으로 별도 관리하며 실제 고객의 선호나 구매 의사를 대체하지 않는다.

### 기록할 데이터와 결과물

실험 버전, 익명 참여자 ID, 기기·화면 크기, 브랜드 인지 여부, 관여도 분류 기준, 단계별 시각, 사용 기능, 오류와 고객 설명을 기록한다. GA4를 사용할 경우 실제 수집·중복·누락 검증을 먼저 수행하며, 이벤트가 이미 연결되었거나 데이터가 수집된 것으로 간주하지 않는다.

1. 인터뷰별 고객 설명과 근거 수준

3. A/B 화면·변경점·동일 조건·과업·측정 기준
4. 실제 테스트 결과와 오류·고객 피드백
