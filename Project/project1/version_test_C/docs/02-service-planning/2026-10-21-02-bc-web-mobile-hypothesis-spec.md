# B·C안 PC 웹→모바일 웹 구매 여정 검증 가설

- 작성일: 2026-10-21
- 상태: 2026-10-21 후속 설계에서 PC→모바일 웹으로 범위를 구체화한 가설. 비교할 구체 UI, 탐색 기준, 판정 수치는 후속 결정 사항이다. 원래 동일 서비스 앱 구매 가설은 [A·B·C 웹→앱 가설](./2026-10-21-01-abc-web-to-app-hypothesis.md)에 정리했다.
- A: SAN SAN GEAR 레퍼런스 클론 / B: ONEPIECE 바이브코딩 버전 / C: ONEPIECE 팀 손코딩 버전. 이번 가설의 직접 비교 대상은 B·C다.
- [FGI 원본 정리](../01-customer-analysis/2026-10-20-01-user-fgi-spec.md), [가상 회원 실행 절차](../03-metrics-validation/2026-10-21-01-member-injection-and-measurement-spec.md)
- 회원 프로필 스키마 revision3에 hypothesis_id, comparison_scope, continuation_channel, continuation_entry_path, target_action, cart_sync_requirement를 추가했다. 기존 device=desktop·entry_path=/·initial_cart_state=empty는 PC 탐색 시작 조건이며 모바일 이어가기 단계의 Cart를 비우라는 뜻이 아니다.

## 1. 출발 가설과 현재 검증 범위

출발 가설:

> 2030대 유저는 웹에서 상품 탐색을 충분히 한 뒤, 구매는 평소 사용이 용이한 앱으로 장바구니를 켜서 바로 결제버튼을 누를 것이다.

이번 구현에서 검증할 ‘앱’의 범위는 **휴대폰 브라우저로 접속하는 모바일 웹**으로 정했다. 인터뷰 고객이 설명한 동일 자사몰 앱 경험은 근거로 보존하되, 이번 실험은 PC 웹과 모바일 웹의 연속 여정을 검증한다.

### 현재 범위에 맞춘 H1

**브랜드를 인지한 20~30대 패션 중·고관여 회원은 PC 웹에서 상품 정보와 옵션을 충분히 탐색해 장바구니에 담은 뒤, 구매를 결정하면 휴대폰의 모바일 웹에서 같은 회원의 장바구니를 열고 추가 상품 탐색을 줄이며 Checkout 버튼을 누를 것이다.**

Checkout 클릭은 구매 단계로 이동하려는 행동이다. 결제 승인 완료·주문 저장·배송 후 구매확정과 각각 구분한다. ‘충분히 탐색’과 ‘바로’의 수치상 문턱을 임의로 정하지 않는다.

## 2. 가설을 분리해서 검증

| 질문 | 검증 방법 | 현재 근거 |
| --- | --- | --- |
| PC 탐색 후 모바일 웹에서 구매를 이어가려 하는가? | 채널 선택을 강제하지 않은 실제 사용자 관찰 | FGI 고객 1의 기존 웹→동일 자사몰 앱 경험에서 얻은 단서. 전체 2030대의 공통 행동으로 검증된 것은 아님 |
| PC에서 담은 Cart가 모바일 웹에서 그대로 이어지는가? | 동일 회원·상품·옵션·수량의 저장·복원 확인 | 새로 검증할 기능 조건 |
| B와 C 중 어느 UI에서 Cart→Checkout 이동 부담이 작은가? | 동일 과업에서 이동·추가 탐색·시간·오류 비교 | 최종 UI 차이와 공통 측정 조건 확정 필요 |

AI에게 PC→모바일 전환을 반드시 하도록 지시한 실행은 경로 재현·성능·계측 점검이다. 그 결과로 ‘2030대가 모바일 구매를 선호한다’고 결론내리지 않는다. 실제 사용자 검증과 AI 시뮬레이션 결과는 별도로 제시한다.

## 3. 비교할 실제 여정

PC 웹 메인 → 목록·상세 탐색 → 실측·소재·관리 정보 확인 → 옵션 선택·Cart 담기 → 추가 비교·재확인 허용 → 모바일 웹 접속 → 동일 회원 인증 확인 → Cart 복원·열기 → 추가 탐색 또는 수량·상품 수정 → Checkout 클릭.

모바일 웹에서도 추가 탐색을 선택할 수 있게 둔다. 전원 Checkout으로 직행하도록 정답 동선을 강제하지 않는다. 탐색 시간이 길다는 이유만으로 불편·실패로 판단하지 않는다.

## 4. 실행 전 필수 조건

1. PC와 실제 휴대폰에서 접근 가능한 테스트 주소가 있어야 한다. 휴대폰의 127.0.0.1은 해당 휴대폰 자신을 가리키므로 PC의 로컬 서버 주소 그대로 사용할 수 없다.
2. 두 기기에서 같은 회원 식별이 유지되고, 해당 회원의 Cart가 서버에 저장·복원되어야 한다. PC localStorage만 사용하는 Cart는 다른 기기에 자동 공유되지 않는다.
3. B·C 각각에서 PC↔모바일 연속성을 확인한다. 비교 사이트 간 Cart를 섞거나 한 사이트에서 수행한 편집이 다른 사이트 초기 조건을 바꾸게 하지 않는다.
4. 상품·옵션·가격·재고, 시작 상태와 기기 조건을 맞추고 비교할 커밋·배포 버전을 고정한다. 구현 방식의 차이만으로 특정 UI 효과를 단정하지 않는다.
5. 로그인·Cart 복원·Checkout 구현 상태를 실제로 확인한다. 미구현 단계에서 멈춘 결과는 구매 의사 이탈과 구분한다.

현재 A 클론의 Cart는 localStorage에 저장한다. B·C의 기기 간 회원 Cart 공유와 실제 기기 측정 준비는 별도로 확인해야 한다. 화면 크기만 바꾸는 실험은 레이아웃 점검이며 실제 기기 간 Cart 복원 검증을 대신하지 않는다.

## 5. 측정 지표와 읽는 법

| 지표 | 계산·관찰 단위 | 해석 조건 |
| --- | --- | --- |
| PC 탐색량 | 상세 조회 수, 정보 확인, 옵션 비교, 활동 시간 | ‘충분히 탐색’의 문턱은 미정. 짧을수록 항상 좋은 지표가 아님 |
| 모바일 전환 비율 | PC에서 Cart에 담은 적격 여정 중 같은 회원으로 모바일에서 이어간 여정 | 전환을 강제하지 않은 트랙에서만 채널 선택 경향으로 읽음 |
| Cart 복원 성공률 | 모바일 복원을 시도한 여정 중 상품·옵션·수량이 일치한 여정 | 기능 성공 지표. 실패는 구매 의사와 분리 |
| 모바일 Cart→Checkout 클릭률 | 적격 모바일 Cart 여정 중 Checkout을 클릭한 여정 | 클릭 총횟수가 아니라 고유 여정 단위로 계산 |
| 추가 탐색 없는 Checkout 비율 | 모바일 Cart 조회 후 새 상품 상세 재탐색 없이 Checkout을 클릭한 여정 | ‘바로’의 사건 순서상 정의. 시간 문턱은 별도 미정 |
| 모바일 구매 단계 이동 부담 | Cart 진입→Checkout 클릭 시간, 화면·클릭 수, 로그인·복원 오류 | 준비 로그인·전환·복원 시간을 함께 남겨 공정하게 비교 |
| 실제 결제 완료 | 승인 완료·주문 저장까지 검증된 경우 별도 집계 | Checkout 클릭·모의 결제는 실제 purchase 성공으로 계산하지 않음 |

시간은 중앙값·분포와 중단 사유를 함께 제시한다. B·C 전체 값만 비교하지 않고 구매 이력·행동 유형·예산·과업 조건도 함께 확인한다. 성향과 구매 과업은 완전한 교차 배분이 아니므로 단순 전체 평균을 성향의 효과로 해석하지 않는다.

## 6. 계측 연결 계획

회원의 일관된 User-ID와 하나의 구매 여정 식별자를 PC·모바일 단계에 연결한다. 기기별 GA 세션이 달라질 수 있으므로 session_id만 같아야 한다는 기준으로 연결하지 않는다. 실제 계정 구조가 사이트마다 다르면 시험 참여자와 인증 계정 간 매핑을 정한다.

- 단계 구분: journey_phase=desktop_exploration / mobile_continuation.
- 장바구니 구분: cart_surface=drawer / page. 상품·옵션·수량 비교를 위해 복원 결과를 기록한다.
- Checkout 클릭: 출발 화면·버튼 위치를 기록하고 화면 진입·결제 완료와 나눈다.
- 검증용 추가 후보: journey_resume, cart_restore_result. 실제 동작에 연결하기 전에는 이미 수집 중인 이벤트로 표현하지 않는다.

구매 이력 0/1/2회 이상은 진입 전 시나리오 속성으로 분석한다. 테스트 이력을 만들기 위해 가짜 과거 purchase 이벤트를 GA4에 전송하지 않는다.

## 7. 확정·미확정·현재 결과

확정: 가설의 핵심은 PC 탐색 후 모바일에서 Cart를 이어 열어 Checkout을 누르는 여정이다. 이번 모바일 범위는 휴대폰 브라우저다. B는 바이브코딩, C는 팀 손코딩 버전이며 같은 프로필·과업을 기준으로 비교한다.

미확정: B·C에서 조작·비교할 구체 UI 차이, ‘충분한 탐색’ 기준, 시간상 ‘바로’의 문턱, 개선 판정 기준, 실제 사용자 실행 구성, 동일 프로필의 사이트별 실행 횟수·순서.

2026-10-21 작성 시점의 결과: 프로필 설계와 개별 계정 로그인·GA4 login 수신을 확인한 단계다. 웹→모바일 Cart 공유와 B·C 여정 비교는 아직 실행 결과가 없다. 2026-10-23(금) 리뷰에서는 확인한 동작·지표·오류·조건·미완료 범위를 근거로 결론을 작성한다.
