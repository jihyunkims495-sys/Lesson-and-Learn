# TIL — Supabase Auth·RLS·CRUD가 연결되는 흐름

- 날짜: 2026-09-10
- Level / Week: LV.2 / Week 6

## 오늘 배운 핵심

Supabase는 단순한 데이터베이스가 아니라 PostgreSQL, 자동 API, 로그인 기능과 RLS를 함께 제공하는 백엔드 플랫폼이다.

오늘 수업의 전체 목적은 다음 흐름을 만드는 것이었다.

```text
사용자 로그인
→ Auth의 사용자 UUID 확인
→ UUID를 회원·상품·주문 데이터에 연결
→ SDK의 CRUD 메서드로 데이터 처리
→ RLS로 사용자별 접근 범위 강제
```

## 헷갈렸던 연결

오늘은 SDK 메서드, 메서드 체이닝, Auth, RLS, Enum, PK·FK, 여러 테이블의 관계가 한꺼번에 등장해 어렵게 느껴졌다.

각 개념을 분리하면 다음과 같다.

- `select()`, `eq()`, `update()`는 데이터 요청 메서드다.
- 메서드 체이닝은 여러 메서드를 이어 쓰는 표현 방식이다.
- 쿼리 빌더는 조건을 차례로 쌓아 요청을 만드는 구조다.
- Auth는 현재 사용자가 누구인지 확인한다.
- FK는 테이블 사이의 데이터 관계를 보장한다.
- RLS는 로그인 사용자가 접근할 수 있는 행을 제한한다.

## 오류에서 배운 점

- Python SDK의 로그인 메서드는 `sign_in_with_password()`다.
- `Email not confirmed`는 코드 문법 문제가 아니라 계정의 이메일 인증 상태 문제다.
- 외래키는 참조하는 컬럼과 자료형이 같아야 한다.
- Table Editor의 Default Value와 제약조건은 서로 다른 설정이다.

## 오늘 만든 것

ERD를 기준으로 `user_details`, `products`, `orders`의 Python CRUD 코드를 작성했다. 삭제는 `deleted_at`을 사용하는 소프트 삭제로 구현했다.

코드 문법과 입력값 검증 테스트는 통과했지만 실제 Supabase 프로젝트 연결과 데이터 변경은 아직 확인하지 않았다.

## 다음 학습
