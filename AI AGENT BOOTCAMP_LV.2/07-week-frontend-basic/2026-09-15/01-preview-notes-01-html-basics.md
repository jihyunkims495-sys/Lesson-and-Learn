- 날짜: 2026-09-15
- Level / Week: LV.2 / Week 7
- 범위: 프론트엔드 개발 1장 1강~3강
- 상태: 수업 전 예습 내용

## 학습 흐름

```text
HTML 기본 구조와 텍스트 의미
→ 블록·인라인 요소의 기본 배치
→ 링크와 상대 경로
→ 이미지·오디오·비디오
→ 폼과 입력값 전송
→ 시멘틱 태그로 문서 영역 구조화
```

HTML은 브라우저 화면의 디자인보다 먼저 콘텐츠의 구조와 의미를 표현하는 마크업 언어다. 1강에서는 기본 문서와 텍스트를 만들고, 2강에서는 문서 연결·미디어·사용자 입력을 추가하며, 3강에서는 페이지 전체를 의미 있는 영역으로 나눈다.

## 1강 — HTML과 텍스트 태그

### 기본 문서 구조

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>문서 제목</title>
</head>
<body>
  <h1>화면 제목</h1>
  <p>본문 문단</p>
</body>
</html>
```

| 구성 | 역할 |
|---|---|
| `<!DOCTYPE html>` | HTML5 문서임을 브라우저에 알림 |
| `html` | 문서 전체의 루트와 기본 언어 지정 |
| `head` | 문자 인코딩·문서 제목·외부 파일 같은 메타데이터 |
| `body` | 사용자 화면에 표시되는 콘텐츠 |

VS Code에서는 `!`를 입력한 뒤 Tab을 누르면 Emmet이 기본 문서 구조를 생성한다.

### 텍스트의 의미

- `h1`~`h6`: 글자 크기가 아니라 문서의 제목 위계를 나타낸다.
- `p`: 하나의 문단을 만든다.
- `strong`: 중요한 내용을 의미적으로 강조한다.
- `em`: 문맥상 강세를 나타낸다.
- `mark`: 현재 문맥에서 눈에 띄게 표시할 내용을 나타낸다.
- `br`: 문단을 나누지 않고 줄만 바꾼다.
- `hr`: 주제의 전환이나 구분을 나타낸다.

HTML은 일반 공백 여러 개를 하나로 합쳐 표시한다. 콘텐츠상 줄바꿈은 `br`, 입력한 형태 보존은 `pre`, 화면 간격 조정은 CSS가 알맞다.

### 블록과 인라인

- 블록 요소는 기본적으로 새 줄에서 시작하며 사용할 수 있는 가로 영역을 차지한다.
- 인라인 요소는 글의 흐름 안에서 필요한 너비만 차지한다.
- `div`는 의미 없는 블록 단위 묶음, `span`은 문장 일부를 묶는 인라인 컨테이너다.

이 구분은 브라우저의 기본 표시 방식이며 CSS `display`로 바꿀 수 있다. 태그 선택은 화면 배치만이 아니라 콘텐츠 의미와 허용되는 중첩 구조도 함께 고려한다.

## 2강 — 링크·멀티미디어·폼

### 링크와 경로

```html
<a href="pages/profile.html">프로필 보기</a>
<a href="https://example.com" target="_blank">새 탭에서 열기</a>
```

- `href`: 이동할 문서나 주소를 지정한다.
- `target`: 링크를 열 위치를 지정한다.
- 절대 경로: 주소 전체 또는 파일 시스템의 기준점부터 표현한다.
- 상대 경로: 현재 HTML 파일의 위치를 기준으로 목적지를 찾는다.

`./`는 현재 폴더, `../`는 상위 폴더를 뜻한다. 상대 경로 오류가 나면 현재 파일에서 목적지까지 폴더를 한 단계씩 추적한다.

### 이미지와 미디어

```html
<img src="images/photo.jpg" alt="공원에서 찍은 풍경">
<video src="media/intro.mp4" controls></video>
```

- `src`: 현재 문서로 불러올 자원의 위치다.
- `alt`: 이미지가 보이지 않거나 보조 기술을 사용할 때 전달할 대체 설명이다.
- `controls`: 오디오·비디오 재생 컨트롤을 표시한다.

`href`는 이동 대상을, `src`는 현재 문서에 불러올 자원을 지정한다는 차이를 기억한다.

### 폼과 입력값

```html
<form action="/signup" method="post">
  <label for="email">이메일</label>
  <input id="email" name="email" type="email">
  <button type="submit">가입</button>
</form>
```

| 속성 | 역할 |
|---|---|
| `action` | 입력값을 보낼 서버 주소 |
| `method` | 요청 방식. 주로 GET 또는 POST |
| `id` | 문서 안에서 요소를 식별하고 `label`과 연결 |
| `name` | 서버에 전달할 데이터의 키 |
| `value` | 실제 전달할 값 또는 선택 항목의 구분값 |

- radio는 같은 `name`을 사용한 그룹에서 하나만 선택한다.
- checkbox는 여러 항목을 독립적으로 선택할 수 있다.
- `textarea`는 여러 줄 입력, `select`와 `option`은 선택 목록을 만든다.
- POST 자체가 암호화를 뜻하지는 않는다. 전송 보호는 HTTPS와 구분해서 생각한다.

## 3강 — HTML5 시멘틱 구조

```text
body
├─ header
│  └─ nav
├─ main
│  ├─ section
│  │  └─ article
│  └─ aside
└─ footer
```

| 태그 | 의미 |
|---|---|
| `header` | 페이지나 구획의 머리말 |
| `nav` | 주요 탐색 링크 모음 |
| `main` | 페이지의 핵심 콘텐츠 |
| `section` | 하나의 주제로 묶은 구획 |
| `article` | 독립적으로 이해·배포할 수 있는 콘텐츠 |
| `aside` | 본문을 보조하는 주변 콘텐츠 |
| `footer` | 페이지나 구획의 꼬리말 |

시멘틱 태그는 검색엔진, 보조 기술, 개발자가 문서 구조를 파악하도록 돕는다. 디자인을 자동으로 완성하지 않으며 화면 표현은 CSS가 담당한다. 의미를 설명할 수 있는 태그가 없고 단순히 묶는 것이 목적일 때 `div`나 `span`을 사용한다.

## 수업 전 확인 질문

1. `head`와 `body`는 어떤 정보를 나누어 담는가?
2. 제목 태그를 글자 크기만 보고 선택하면 안 되는 이유는 무엇인가?
3. `href`와 `src`는 각각 어떤 대상을 지정하는가?
4. 입력 요소에 `name`이 없으면 폼 제출 데이터에 어떤 차이가 생기는가?
5. radio와 checkbox의 선택 방식은 어떻게 다른가?
6. `section`과 `article`은 어떤 기준으로 선택하는가?
7. 시멘틱 태그로 바꾸면 화면 디자인도 자동으로 바뀌는가?

## 수업 중 확인할 것

- 실제 폴더 구조에서 링크와 이미지 상대 경로가 동작하는지
- 개발자 도구에서 HTML 중첩과 기본 `display` 값을 확인할 수 있는지
- 폼 제출 시 어떤 `name=value`가 만들어지는지
- `label`의 `for`와 입력 요소의 `id`가 올바르게 연결됐는지
- 각 시멘틱 영역의 역할을 코드만 보고 설명할 수 있는지
