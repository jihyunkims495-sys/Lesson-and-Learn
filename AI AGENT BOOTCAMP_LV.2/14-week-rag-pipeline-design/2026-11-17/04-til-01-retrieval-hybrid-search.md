# TIL | 2026-11-17 | Retriever와 Hybrid Search

> LV.2 / Week 14 · RAG 검색 파이프라인

> **검색기는 문서를 가져오는 데서 끝나지 않고, 어떤 문서를 왜 통과시켰는지 단계별로 검증해야 한다.**

> Top-k, 관련도 임계값, BM25와 벡터 검색의 결합이 각각 다른 검색 실패를 줄이는 장치라는 점을 이해했다.

---

## 1. What — 무엇을 배웠는가?

### 핵심 개념

- Top-k는 반환 개수이고 score threshold는 최소 관련도 기준이다.
- BM25는 정확한 단어 일치에 강하고, 벡터 검색은 표현이 달라도 의미가 비슷한 문서를 찾는 데 강하다.
- Hybrid Search는 두 검색 결과를 결합하지만, 가중치와 후보 순위를 검증하지 않으면 무관한 문서가 상위에 남을 수 있다.
- 검색 결과의 품질과 LLM 생성 성공 여부는 별도로 확인해야 한다.

### 핵심 코드

```python
hybrid_retriever = EnsembleRetriever(
    retrievers=[bm25_retriever, vector_retriever],
    weights=[0.5, 0.5],
)

retrieved_docs = hybrid_retriever.invoke(query)
```

### 오늘 수행한 실습

- 프로젝트 전용 Python 환경과 Jupyter 커널을 설정했다.
- 규정 예제 문서로 BM25 검색기를 구성했다.
- 문서를 임베딩해 PGVector 검색기를 만들었다.
- BM25와 벡터 검색을 0.5:0.5로 결합해 Hybrid 검색 결과를 확인했다.
- 검색 문맥을 LLM 프롬프트에 연결했지만 최종 호출은 모델 접근 권한 문제로 완료하지 못했다.


## 2. Why — 왜 필요한가?

### 이 개념이 필요한 이유

Top-k만 사용하면 질문과 관련된 문서가 없어도 정해진 수만큼 결과가 반환될 수 있다. 이런 문서가 LLM 문맥에 들어가면 자연스럽지만 근거가 부족한 답변이 만들어질 수 있다.

BM25만 사용하면 동의어나 구어체 표현을 놓칠 수 있고, 벡터 검색만 사용하면 오류 코드나 고유명사의 정확한 문자열이 뭉개질 수 있다. 두 검색 방식을 결합하면 서로 다른 실패 조건을 보완할 수 있다.

### 내 생각

> 처음에는 검색 결과가 나오면 Retriever가 정상이라고 생각하기 쉬웠다. 오늘은 결과가 존재하는 것과 질문에 충분히 관련된 문서가 상위에 있는 것이 다르다는 점을 알게 됐다. 앞으로는 최종 답변보다 먼저 검색 후보와 순위를 출력해 확인해야겠다.

---

## 3. How — 어떻게 작동하는가?

### 작동 과정

1. 문서를 BM25용 토큰과 임베딩 벡터로 준비한다.
2. BM25는 키워드 일치를, 벡터 검색은 의미적 유사도를 기준으로 후보를 찾는다.
3. EnsembleRetriever가 두 검색기의 순위를 가중치에 따라 결합한다.
4. 선택된 문서의 본문을 하나의 문맥으로 연결한다.
5. 프롬프트가 문맥과 질문을 LLM에 전달한다.
6. 최종 답변이 검색 문서의 근거 안에서 생성됐는지 다시 검사한다.

### 내 말로 설명하기

> Hybrid Search는 같은 질문을 서로 다른 기준으로 두 번 검색한 뒤 결과를 합치는 방법이다. BM25는 글자가 정확히 맞는 정보를 찾고, 벡터 검색은 표현이 달라도 뜻이 비슷한 정보를 찾는다. 둘을 합친 뒤에도 검색 순위가 적절한지 확인해야 하고, 마지막 LLM 답변은 검색 근거와 별도로 검증해야 한다.

## 5. 오늘의 문제 해결

### 해결한 문제

- `langchain_community.retriever`를 복수형 `retrievers`로 수정했다.
- `search_knargs`와 `socre_threshold`를 올바른 인자명으로 수정했다.
- `PGVector.from_documents()`에 `embedding=embeddings`를 전달하도록 수정했다.
- 노트북 커널의 표시 이름이 아니라 실제 Python 실행 환경을 확인했다.

### 아직 해결하지 못한 문제

- 최종 LLM 호출은 현재 프로젝트의 모델 접근 권한 부족으로 실패했다.
- 접근 가능한 모델을 확인한 뒤 같은 검색 문맥으로 다시 실행해야 한다.

### 해결 원리

> traceback의 마지막 문장만 보는 대신 import, 환경, 검색기 생성, 검색 실행, 모델 호출 단계를 나누었다. 각 단계에서 처음 잘못된 상태가 되는 위치를 찾으니 코드 오타와 외부 권한 문제를 구분할 수 있었다.
