## 1. What — 무엇을 배웠는가?

오늘은 브라우저에서 사용자의 행동을 처리하는 이벤트와, 서버 통신처럼 시간이 걸리는 작업을 처리하는 비동기 방식의 기본 구조를 배웠다.

### 이벤트와 이벤트 전파

- 이벤트는 클릭, 키 입력, 폼 제출처럼 브라우저에서 발생하는 행동이나 상태 변화다.
- 이벤트 리스너는 이벤트가 발생했을 때 실행되는 함수다.
- 한 번의 클릭으로 만들어진 이벤트는 DOM 계층을 따라 캡처링 → 타깃 → 버블링 단계로 이동한다.
- 이벤트 전파는 부모 요소도 자식 요소에서 일어난 사건을 처리할 수 있게 한다.
- 자식과 부모의 동작이 충돌할 때 `stopPropagation()`으로 이후 전파를 막을 수 있다.
- 링크 이동이나 폼 제출 같은 브라우저 기본 동작은 `preventDefault()`로 취소한다.

### 이벤트 객체

```javascript
element.addEventListener("click", function (event) {
  console.log(event.target);
  console.log(event.currentTarget);
});
```

- `event.target`: 실제로 클릭한 요소
- `event.currentTarget`: 현재 리스너가 등록된 요소
- 두 항목은 메서드가 아니라 이벤트 객체의 프로퍼티다.

### 프로퍼티와 메서드

```text
프로퍼티 → 객체가 가진 정보나 상태
메서드   → 객체가 수행하는 행동
```

```javascript
event.target;            // 프로퍼티
event.stopPropagation(); // 메서드
```

### `this`

- 일반 함수의 `this`는 함수의 호출 방식에 따라 달라진다.
- 일반 함수 이벤트 리스너에서는 보통 리스너가 등록된 DOM 요소를 가리킨다.
- 화살표 함수는 자기만의 `this`를 만들지 않고 바깥쪽 값을 이어받는다.
- 이벤트 처리에서는 `event.currentTarget`을 사용하면 대상이 더 분명해질 수 있다.

### 동기·비동기와 AJAX

- 동기 처리는 앞 작업이 끝난 다음에 다음 작업을 실행한다.
- 비동기 처리는 시간이 걸리는 작업을 기다리는 동안 다른 작업을 계속 처리한다.
- 이벤트와 서버 응답은 발생하거나 완료되는 시간을 미리 알 수 없으므로 비동기 구조가 필요하다.
- AJAX는 서버와 비동기로 데이터를 주고받아 페이지 전체를 새로고침하지 않고 필요한 부분만 바꾸는 방식이다.
- `fetch()`는 AJAX 통신을 구현할 때 사용할 수 있는 Web API다.

```text
사용자 클릭
→ 이벤트 발생
→ 서버에 비동기 요청
→ JSON 응답 수신
→ 필요한 DOM만 변경
```

## 2. Why — 왜 필요한가?

사용자가 버튼을 클릭하거나 입력하는 동안 웹페이지가 적절히 반응하려면 이벤트를 처리해야 한다. 서버에서 데이터를 가져오는 동안 페이지 전체가 멈추지 않게 하려면 비동기 처리가 필요하다.

이벤트 전파를 이해하면 중첩된 요소에서 부모와 자식의 클릭이 왜 함께 실행되는지 알 수 있고, 필요한 경우 처리 범위를 조절할 수 있다. AJAX를 이해하면 좋아요, 자동완성, 댓글, 장바구니처럼 새로고침 없이 화면 일부가 바뀌는 기능의 기본 원리를 파악할 수 있다.

### 내 생각

오늘은 개념 하나하나보다 서로 연결되는 용어가 너무 많아서 훨씬 어렵게 느껴졌다. 이벤트, 이벤트 객체, 프로퍼티, 메서드, `this`, 전파, 동기·비동기, AJAX가 한꺼번에 나오자 앞에서 들은 내용이 뒤의 개념과 어떻게 이어지는지 놓쳤다.

특히 “이벤트가 왜 전파되는지”, “전파한 이벤트를 왜 다시 차단하는지”, “`target`과 `currentTarget`은 메서드인지”, “프로퍼티가 무엇인지”를 계속 다시 확인해야 했다. 오늘은 이해를 완료한 날이 아니라, 내가 어디에서 막히는지 확인한 날에 가깝다.

## 3. How — 어떻게 작동하는가?

### 브라우저 이벤트 흐름

1. 브라우저가 클릭이나 입력 같은 사용자 행동을 감지한다.
2. 브라우저가 발생 정보를 담은 이벤트 객체를 만든다.
3. 이벤트가 DOM 계층을 따라 실제 타깃까지 전달된다.
4. 등록된 이벤트 리스너가 실행된다.
5. 이벤트가 부모 방향으로 버블링된다.
6. 필요한 경우 전파 또는 브라우저 기본 동작을 차단한다.

### 비동기 통신 흐름

1. 사용자 이벤트를 계기로 JavaScript가 서버 요청을 시작한다.
2. 브라우저는 응답을 기다리는 동안 다른 화면 작업을 계속 처리한다.
3. 응답이 도착하면 JavaScript가 데이터를 읽는다.
4. 받은 데이터로 필요한 DOM만 변경한다.

### 내 말로 설명하기

이벤트는 사용자가 웹페이지에서 한 행동이고, 이벤트 리스너는 그 행동이 발생했을 때 실행할 함수다. 클릭 이벤트는 중첩된 DOM 구조를 따라 이동하기 때문에 부모 요소에서도 처리할 수 있다. 부모까지 실행되면 안 되는 상황에는 전파를 막는다.

서버 응답처럼 시간이 걸리는 작업은 기다리는 동안 화면 전체를 멈추게 할 수 없어서 비동기로 처리한다. AJAX는 이런 비동기 통신을 사용해 새로고침 없이 필요한 화면만 바꾸는 방식이다.

> 위 설명은 오늘 받은 보충 설명을 정리한 문장이다. 독립적으로 다시 설명하거나 코드에 적용한 근거는 아직 없다.

## 4. 오늘의 문제 해결

오늘은 실행 오류를 해결한 것이 아니라 개념의 의미를 다시 구분했다.

| 처음 헷갈린 내용 | 보강한 구분 |
|---|---|
| 이벤트 전파는 여러 번 클릭하는 과정인가? | 한 번의 클릭 이벤트가 DOM 조상 경로를 이동하는 과정 |
| 전파 차단은 부분 선택 기능인가? | 이벤트가 처리되는 범위를 제한하는 기능 |
| `target`과 `currentTarget`은 메서드인가? | 이벤트 객체가 가진 프로퍼티 |
| 프로퍼티란 무엇인가? | 객체가 가진 정보나 상태 |
| 왜 동기·비동기를 배우는가? | 이벤트·서버 응답을 기다리면서도 화면이 멈추지 않게 하기 위해서 |
| AJAX란 무엇인가? | 새로고침 없이 서버와 비동기 통신하고 필요한 화면만 변경하는 방식 |

코드 실행이나 오류 메시지 확인은 하지 않았으므로 실행 오류를 해결했다고 기록하지 않는다.

### Problem — 개선할 것

- 오늘 강의는 너무 어려웠고, 무엇이 무슨 말인지 전체 흐름을 거의 잡지 못했다.

- 이벤트 전파와 전파 차단을 화면의 부분 선택 기능처럼 받아들였다.
- 동기·비동기와 AJAX가 이벤트 학습 다음에 왜 연결되는지 처음에는 이해하기 어려웠다.
- 설명 예시는 읽었지만 직접 실행한 코드와 출력 결과가 없어 실제 동작을 확인하지 못했다.

### Try — 다음에 시도할 것

- 한 파일에서 부모 `div`와 자식 `button`만 만들어 이벤트 전파를 눈으로 확인한다.

- `setTimeout()` 세 개의 예상 출력 순서와 실제 출력 순서를 비교한다.
- `fetch()` GET 요청 한 개만 실행해 요청 → 응답 → JSON → 화면 변경 흐름을 따라간다.
- 여러 개념을 한꺼번에 외우지 않고 이벤트와 비동기를 각각 작은 예제로 나누어 복습한다.
