- 기록 상태: 실제 질의응답 기반 학습 정리 / 코드 실행 및 이해도 평가 미실시

## 1. 오늘 학습의 전체 연결

```text
HTML 요소
→ 브라우저가 DOM 객체로 표현
→ 사용자의 클릭·입력으로 이벤트 발생
→ 이벤트 객체가 발생 정보 전달
→ 이벤트 리스너가 동작 실행
→ 필요하면 전파 또는 기본 동작 제어
→ 시간이 걸리는 서버 요청은 비동기로 처리
→ 응답을 받은 뒤 필요한 DOM만 변경
```

오늘은 개별 문법을 외우는 것보다 다음 연결을 이해하는 것이 핵심이었다.

```text
이벤트 → 이벤트 객체 → 리스너 → DOM 변경
이벤트 전파 → 부모·자식 처리 범위 조절
비동기 처리 → 서버 응답을 기다리는 동안 화면 유지
AJAX → 비동기 서버 통신 후 화면 일부 변경
```

## 2. 실제로 다룬 질문과 개념

### 2.1 JavaScript, TypeScript, Node.js

- JavaScript는 브라우저와 Node.js에서 실행되는 프로그래밍 언어다.
- TypeScript는 JavaScript에 정적 타입 검사를 추가하고, 실행 전에 JavaScript로 변환한다.
- Node.js는 JavaScript를 브라우저 밖의 컴퓨터나 서버에서 실행하는 런타임이다.
- 브라우저에는 DOM과 `window`가 있지만 일반적인 Node.js 환경에는 HTML 문서와 DOM이 기본 제공되지 않는다.

### 2.2 이벤트와 이벤트 리스너

- 이벤트는 클릭, 키 입력, 스크롤, 폼 제출처럼 브라우저에서 발생하는 행동이나 상태 변화다.
- 이벤트 리스너는 특정 이벤트가 발생했을 때 실행할 함수다.
- 이벤트가 발생하면 브라우저가 이벤트 객체를 만들고 리스너에 전달한다.

```javascript
button.addEventListener("click", function (event) {
  message.textContent = "버튼을 클릭했습니다.";
});
```

```text
버튼 클릭
→ click 이벤트 발생
→ 이벤트 객체 생성
→ 등록된 함수 실행
→ DOM 변경
```

### 2.3 이벤트 전파

중첩된 DOM에서 자식 요소를 한 번 클릭하면 하나의 이벤트가 조상 경로를 따라 이동한다.

```text
Window → Document → html → body → 부모 → 타깃
                                      ↓
Window ← Document ← html ← body ← 부모 ← 타깃
```

- 캡처링: 상위 객체에서 실제 클릭 대상까지 내려가는 단계
- 타깃: 이벤트가 실제 발생한 요소에 도달한 단계
- 버블링: 실제 클릭 대상에서 조상 요소 방향으로 올라가는 단계

이 전파 덕분에 부모 요소가 자식에서 발생한 이벤트도 처리할 수 있다. 목록의 여러 버튼을 부모 하나에서 처리하는 이벤트 위임이 대표적인 활용이다.

### 2.4 이벤트 전파를 차단하는 이유

이벤트 전파 자체는 유용하지만 자식과 부모가 서로 다른 동작을 해야 할 때 충돌할 수 있다.

```text
상품 카드 클릭 → 상세 페이지 이동
카드 안 삭제 버튼 클릭 → 상품 삭제
```

삭제 버튼의 클릭이 카드까지 버블링되면 삭제와 상세 페이지 이동이 함께 실행될 수 있다. 이때 `stopPropagation()`으로 부모 방향의 이후 전파를 막는다.

```javascript
deleteButton.addEventListener("click", function (event) {
  event.stopPropagation();
  console.log("상품 삭제");
});
```

- `stopPropagation()`: 부모·조상 요소로 이어지는 이벤트 전파 차단
- `preventDefault()`: 링크 이동이나 폼 제출 같은 브라우저 기본 동작 취소

이벤트 차단은 부분 선택 기능이 아니라, 이미 선택된 요소에서 발생한 이벤트를 어느 범위까지 처리할지 제한하는 기능이다.

### 2.5 `target`과 `currentTarget`

둘 다 이벤트 객체가 가진 프로퍼티다.

| 프로퍼티 | 의미 |
|---|---|
| `event.target` | 사용자가 실제로 클릭한 가장 안쪽 요소 |
| `event.currentTarget` | 현재 실행 중인 리스너가 등록된 요소 |

부모 `ul`에 리스너를 등록하고 내부 `button`을 클릭했다면:

```text
event.target        → button
event.currentTarget → ul
```

### 2.6 프로퍼티와 메서드

- 프로퍼티는 객체가 가진 정보나 상태다.
- 메서드는 객체가 수행할 수 있는 함수다.

```javascript
event.target;            // 프로퍼티: 정보 읽기
event.currentTarget;     // 프로퍼티: 정보 읽기
event.stopPropagation(); // 메서드: 행동 실행
event.preventDefault();  // 메서드: 행동 실행
```

괄호 `()`의 유무는 초반에 프로퍼티와 메서드를 구분하는 실용적인 단서가 된다.

### 2.7 이벤트 리스너와 `this`

`this`는 함수가 작성된 위치보다 어떻게 호출됐는지에 따라 가리키는 값이 달라진다.

- `user.introduce()`에서 `this`는 `user`다.
- 일반 함수 이벤트 리스너의 `this`는 보통 리스너가 등록된 DOM 요소다.
- 화살표 함수는 자신의 `this`를 만들지 않고 바깥쪽 `this`를 이어받는다.
- 이벤트 요소를 명확히 사용할 때는 `event.currentTarget`을 사용할 수 있다.
- `bind(user)`는 나중에 함수가 어디에서 호출돼도 `this`를 `user`로 고정한다.

### 2.8 동기와 비동기

- 동기 처리는 앞 작업이 끝나야 다음 작업을 실행한다.
- 비동기 처리는 시간이 걸리는 작업을 브라우저에 맡기고 JavaScript가 다음 코드를 계속 처리한다.

동기와 비동기를 배우는 이유는 사용자의 클릭과 서버 응답처럼 발생·완료 시점을 미리 알 수 없는 작업을 처리하면서도 화면이 멈추지 않게 하기 위해서다.

```text
이벤트 리스너 등록
→ 사용자가 클릭할 때까지 다른 작업 처리
→ 클릭 시 콜백 실행

서버 요청 전송
→ 응답을 기다리는 동안 다른 작업 처리
→ 응답 도착 후 결과 처리
```

### 2.9 AJAX

AJAX는 별도의 언어나 특정 라이브러리가 아니다. JavaScript가 서버와 비동기로 데이터를 주고받고 페이지 전체를 새로고침하지 않은 채 필요한 화면 부분만 바꾸는 개발 방식이다.

```text
사용자 이벤트
→ fetch 등으로 서버 요청
→ 서버 응답 수신
→ JSON 데이터 사용
→ 필요한 DOM만 변경
```

- AJAX: 전체 비동기 통신 방식
- `fetch()`: AJAX 방식의 통신을 구현하는 Web API 중 하나
- JSON: 서버와 주고받는 데이터 형식으로 자주 사용

## 3. 헷갈렸던 지점과 보강 설명

1. 이벤트 전파가 여러 번 클릭하는 과정을 뜻하는지 혼란이 있었다.
   - 한 번의 클릭으로 생성된 하나의 이벤트가 DOM 조상 경로를 따라 이동하는 과정이다.
2. 이벤트 전파 차단을 부분 선택 기능으로 이해했다.
   - 선택 기능이 아니라 이벤트의 후속 처리 범위를 제한하는 기능이다.
3. `event.target`과 `event.currentTarget`을 메서드로 생각했다.
   - 두 항목은 이벤트 객체의 정보를 담는 프로퍼티다.
4. 프로퍼티의 의미를 다시 확인했다.
   - 프로퍼티는 객체의 정보, 메서드는 객체의 행동이다.
5. `this`가 언제 무엇을 가리키는지 혼란이 있었다.
   - 일반 함수는 호출 방식에 따라 `this`가 정해지고 화살표 함수는 바깥쪽 `this`를 이어받는다.
6. 이벤트 다음에 동기·비동기를 배우는 이유가 불분명했다.
   - 이벤트와 서버 응답은 실행 시점이 정해지지 않으므로, 화면을 멈추지 않고 나중에 결과를 처리하는 구조가 필요하다.

## 4. 실행 및 이해 근거

- 개념 질문을 중심으로 예제와 실행 흐름을 정리했다.
- 이벤트 전파 차단을 “부분 선택 기능”으로 이해한 뒤 “처리 범위 제한”으로 다시 구분했다.
- 직접 작성하거나 실행한 코드는 기록되지 않았다.
- 브라우저 화면, 콘솔 출력, 네트워크 요청, 오류 메시지와 해결 결과는 확인하지 않았다.
- 설명을 들은 뒤 독립적으로 다시 설명하거나 변형 예제에 적용한 근거는 없다.
- 따라서 전체 이해도는 미확인이다.
