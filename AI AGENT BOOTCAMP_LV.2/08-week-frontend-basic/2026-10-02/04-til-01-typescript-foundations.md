# TIL | 2026-10-02 | TypeScript 1장~4장 2강

- Level / Week: LV.2 / Week 8
- 실제 수업 범위: 프론트엔드 심화 TypeScript 1장 1강~4장 2강

> 아침에 TypeScript를 처음 시작했는데 4장 2강까지 달렸다. 오늘은 이해보다 진도가 빨랐고, 그래서 더 솔직하게 학습 상태를 남기기로 했다.

> TypeScript는 변수·함수·객체가 지켜야 할 타입의 약속을 코드에 적고 실행 전에 검사하도록 돕는다.

---

## 1. What — 무엇을 배웠는가?

### 실제 수업 범위

- 1장: JavaScript의 한계, TypeScript의 등장, 실습 환경
- 2장: 원시 타입, 배열과 튜플, `any`·`unknown`·`never`, 타입 추론과 단언
- 3장: 함수의 매개변수·반환 타입, 함수 표현식과 콜백
- 4장: 타입 별칭, 인터페이스, `readonly`, 인덱스 시그니처, 인터페이스 확장

### 오늘 붙잡은 핵심 개념

- `.ts`는 TypeScript 파일이며, 일반적으로 도구가 JavaScript로 변환한 결과를 실행한다.
- `const`는 변수의 재할당을 막고, 재할당이 필요한 경우에는 `let`을 사용한다.
- `any`는 타입 검사를 대부분 우회하지만 `unknown`은 값을 확인한 뒤 사용하게 한다.
- 함수 타입은 입력인 매개변수와 출력인 반환값의 약속을 함께 표현한다.
- 인터페이스는 객체의 설계도이고 `extends`는 기존 설계도에 항목을 추가한다.
- 인덱스 시그니처는 이름이 미리 정해지지 않은 객체 속성의 값 타입을 제한한다.

### 핵심 코드

```typescript
const course: string = "TypeScript";

interface Product {
  name: string;
  price: number;
}

interface FashionProduct extends Product {
  size: string;
}

interface SizeStock {
  [size: string]: number;
}
```

위 코드는 오늘 개념을 압축하기 위한 예시다. 실제 실행 결과를 확인한 실습으로 기록하지 않는다.

### 오늘 수행한 실습

- 실제 코드 실행·출력·오류 해결은 확인하지 못했다.
- 따라서 별도의 Practice 완료 기록은 만들지 않는다.

---

## 2. Why — 왜 필요한가?

JavaScript에서는 값의 종류가 맞지 않아도 문제가 실행 중에 드러날 수 있다. TypeScript는 변수, 함수와 객체의 모양을 타입으로 적어 코드가 약속을 어기는 부분을 실행 전에 찾도록 돕는다.

```text
변수의 값에 타입 약속
→ 함수의 입력과 출력에 타입 약속
→ 객체 전체에 타입 약속
→ 공통 객체 설계도를 확장해 재사용
```

### 내 생각

> 오늘 수업에서는 문법이 끝없이 새로 나오는 것처럼 느껴졌다. 다시 정리해 보니 모든 내용이 완전히 따로 떨어진 것은 아니었다. 변수 하나의 타입에서 시작해 함수의 타입으로, 다시 객체의 설계도로 범위가 커지고 있었다.

---

## 3. How — 어떻게 연결되는가?

### TypeScript 코드의 실행 흐름

```text
.ts 파일 작성
→ TypeScript 도구가 타입을 검사
→ TypeScript 전용 타입 문법을 제거·변환
→ JavaScript 결과 생성
→ JavaScript 실행 환경에서 실행
```

### 1장부터 4장까지의 연결

```text
1장: 타입 검사가 왜 필요한가
→ 2장: 값에는 어떤 타입을 붙이는가
→ 3장: 함수의 입력과 출력은 어떻게 표현하는가
→ 4장: 객체의 전체 모양은 어떻게 설계하고 확장하는가
```

### 내 말로 설명하기

> TypeScript는 새로운 실행 엔진이라기보다 JavaScript를 작성할 때 타입이라는 안전장치를 더하는 도구다. 인터페이스는 객체의 설계도이고, `extends`는 그 설계도를 복사해서 필요한 항목을 더하는 방법이다.

이 설명은 오늘 제공받은 코치 설명을 바탕으로 정리한 초안이다. 예제 작성이나 실행을 통한 이해 확인은 아직 하지 않았다.

---

## 4. 오늘의 멘붕 기록

### 상황

아침에 TypeScript를 시작했다. 처음에는 “TypeScript가 무엇인가”를 묻고 있었는데, 수업은 빠르게 기본 타입과 함수 타입을 지나 4장 2강의 인덱스 시그니처와 인터페이스 확장까지 넘어갔다.

머릿속에서 앞 개념을 정리하기도 전에 다음 용어가 들어왔다. `any`, `unknown`, 컴파일, 트랜스파일, `const`, 인터페이스와 상속이 한꺼번에 겹치면서 집중이 끊겼다. 솔직한 감정은 “도망가고 싶다”였다.

### 오늘 바꾼 방식

완벽하게 이해하면서 진도를 따라가려는 목표를 잠시 내려놓았다.

```text
강의 제목 남기기
→ 핵심 단어 3개 남기기
→ 이해되지 않은 부분에 ??? 표시하기
→ 나중에 한 개념씩 다시 연결하기
```

오늘의 혼란을 “나는 프로그래밍을 못한다”는 결론으로 만들지 않기로 했다. 오늘 확인된 사실은 학습 능력이 아니라, 새 용어를 처리할 시간보다 수업 속도가 빨랐다는 것이다.

## 5. KPT 회고

### Keep — 계속할 것

- 모르는 단어를 아는 척 넘기지 않고 바로 질문했다.
- `pass`, 임베딩처럼 이미 아는 개념과 비교해 차이를 확인했다.
- 이해가 끊겼다는 상태를 숨기지 않고 학습 속도 조절을 요청했다.
- 긴 설명을 변수 → 함수 → 객체 설계도라는 큰 흐름으로 다시 접었다.

### Problem — 개선할 것

- 개념 하나를 정리하기 전에 다음 장으로 넘어가 용어가 서로 섞였다.
- 컴파일과 실행, 타입 검사와 런타임 검증의 경계가 아직 선명하지 않다.
- `any`·`unknown`, 콜백, 인터페이스와 인덱스 시그니처를 실제 코드로 확인하지 못했다.
- 설명을 들었지만 직접 작성하거나 실행하지 않아 이해 여부를 판단할 근거가 없다.

### Try — 다음에 시도할 것

1. 1장~4장을 네 덩어리로 나눠 한 번에 한 덩어리만 복습한다.
2. 개념마다 코드 한 개만 직접 실행하고 결과를 기록한다.
3. `const`·`let` → `any`·`unknown` → 함수 타입 → 인터페이스 순서로 다시 연결한다.
4. 4장 2강에서는 패션 상품과 사이즈별 재고 예시만 사용해 `extends`와 인덱스 시그니처를 확인한다.

## 6. 이해도 점검

- [ ] TypeScript와 JavaScript의 관계를 내 말로 설명할 수 있다.
- [ ] `.ts`가 JavaScript로 변환되어 실행되는 순서를 설명할 수 있다.
- [ ] `const`와 `let`의 사용 기준을 예제 없이 설명할 수 있다.
- [ ] `any`와 `unknown`의 차이를 코드로 확인했다.
- [ ] 함수의 매개변수·반환 타입과 콜백 타입을 읽을 수 있다.
- [ ] 인터페이스·인덱스 시그니처·`extends`를 직접 작성할 수 있다.

### 현재 상태

- 사용자 자기보고: 거의 이해하지 못했고 집중이 어려웠음
- 코치 평가: 실시하지 않음
- 실제 코드 적용: 확인되지 않음
- 결론: 이해도를 확정하지 않고 다음 복습에서 작은 코드로 확인한다.
