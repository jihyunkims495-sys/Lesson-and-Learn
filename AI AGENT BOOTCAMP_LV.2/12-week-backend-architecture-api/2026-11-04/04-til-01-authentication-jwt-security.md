# TIL | 2026-11-04 | 인증·인가와 JWT 보안 흐름

> LV.2 · Week 12 · 백엔드 아키텍처 & API 설계

> **인증의 전체 흐름을 Token·JWT·HMAC과 4계층의 책임으로 연결해 정리했다.**

---

## 1. What — 무엇을 배웠는가?

### 핵심 개념

- 인증은 사용자가 누구인지 확인하고, 인가는 인증된 사용자가 어떤 행동을 할 수 있는지 판단한다.
- OAuth는 외부 서비스의 권한을 위임받기 위한 표준이며, 그 자체가 사용자 인증 전체를 뜻하지는 않는다.
- JWT는 Token 형식 중 하나이고, HMAC Signature는 내용의 암호화가 아니라 변조 여부 확인에 사용된다.
- PyJWT는 JWT 생성과 검증을 돕지만 만료 정책, 로그아웃, 권한 검사는 애플리케이션에서 설계해야 한다.
- `passlib[bcrypt]`의 대괄호는 Bcrypt 관련 선택 의존성을 함께 설치한다는 의미다.
- `Generic[T]`를 사용하면 공통 응답 구조를 유지하면서 내부 데이터 타입을 구체화할 수 있다.

### 핵심 코드

```python
token = jwt.encode(payload, secret_key, algorithm="HS512")
claims = jwt.decode(token, secret_key, algorithms=["HS512"])
```

이 코드는 오늘 읽고 정리한 JWT 사용 형태다. 실제 키와 실행 환경을 연결한 동작 검증은 아직 하지 않았다.

### 오늘 수행한 학습

- 프로젝트의 인증 코드를 계층별로 읽고 로그인·로그아웃 흐름을 연결했다.
- 인증 관련 Python 파일 12개의 정적 구문 구조를 확인했다.
- 서버 기동, 데이터베이스 연결, HTTP 요청은 실행하지 않았다.

### 실제 작성한 코드와 검증 상태

```text
작성한 코드: 프로젝트 코드 변경 없음
검증 방법: 인증 관련 Python 파일의 정적 구문 검사
확인한 결과: 대상 12개 파일이 모두 파싱됨
미완료: 서버·데이터베이스·HTTP 환경에서 로그인, 로그아웃, Token 차단, 401·403 검증
```

## 2. Why — 왜 필요한가?

- 인증과 인가를 분리해야 로그인 성공과 기능 사용 권한을 서로 다른 규칙으로 관리할 수 있다.
- 비밀번호를 단방향 해시로 저장하면 저장소가 노출되어도 원문 비밀번호가 바로 드러나는 위험을 줄일 수 있다.
- JWT의 만료, 서명, 차단 정책을 구분해야 Token이 있다고 해서 무조건 접근을 허용하는 실수를 막을 수 있다.
- 계층별 책임을 나누면 인증 정책과 JWT·DB 같은 기술 구현을 독립적으로 변경하고 테스트하기 쉬워진다.

---

## 3. How — 어떻게 작동하는가?

### 작동 과정

1. 로그인 요청이 들어오면 입력 형식을 검증한다.
2. 사용자 정보를 조회하고 입력한 비밀번호를 저장된 해시와 비교한다.
3. 인증에 성공하면 사용자 식별자와 만료 시각 등을 Claim으로 담아 Token을 발급한다.
4. 보호된 API는 Signature, 만료, Token 종류와 차단 여부를 검증한다.
5. 검증된 사용자의 권한을 확인한 뒤 요청한 기능의 실행 여부를 결정한다.

### 비유로 정리하기

Token은 출입증과 비슷하다. 인증은 출입증을 받을 사람이 맞는지 확인하는 과정이고, 인가는 그 출입증으로 어느 공간까지 들어갈 수 있는지 판단하는 과정이다. JWT Signature는 출입증의 내용을 숨기기보다 누군가 내용을 바꾸지 않았는지 확인하는 봉인에 가깝다.

## 7. KPT 회고

### Keep — 계속할 것

- 비슷해 보이는 용어를 “무엇을 확인하는가”와 “누가 책임지는가”로 나누어 비교한다.
- 라이브러리의 기능과 애플리케이션의 보안 정책을 구분해서 읽는다.

### Problem — 개선할 것

- 정적 검사까지만 수행해 실제 로그인·로그아웃과 Token 차단 동작은 확인하지 못했다.
- 개념을 직접 설명하거나 코드를 작성하는 별도 이해도 평가는 진행하지 않았다.

### Try — 다음에 시도할 것

- 실제 요청으로 로그인부터 보호 API 접근까지 순서대로 추적한다.
- 로그아웃 전후 동일 Token의 결과와 차단 목록 상태를 비교한다.
- 인증 실패 401과 권한 부족 403을 각각 재현한다.
