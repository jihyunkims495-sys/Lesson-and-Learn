# TIL | 2026-10-15 | ONEPIECE Cart와 React의 상태·렌더링 흐름

- 학습 구분: LV.2 / Week 9
- 담당 작업: ONEPIECE 장바구니(Cart)

> Cart를 구현하면서 파일마다 맡는 역할과, 여러 함수가 있는 컴포넌트에서 화면이 만들어지는 흐름을 연결했다.

> 이벤트 함수는 상태를 변경하고, React는 변경된 상태를 읽는 컴포넌트를 다시 렌더링하여 JSX에 반영한다.

## 1. What — 무엇을 배웠는가?

### 핵심 개념

- Next.js의 `page.tsx`는 해당 경로의 화면을 구성하는 페이지 컴포넌트다. 도메인 컴포넌트를 불러와 조합하고 이벤트 함수를 연결할 수 있다.
- 하나의 컴포넌트 안에 여러 함수를 선언할 수 있다. 어떤 함수가 무엇을 반환하는지, 그 반환값을 누가 사용하는지를 구분해야 한다.
- 이벤트 함수가 실행된다는 것과 화면용 JSX를 반환한다는 것은 서로 다른 역할이다. `CartPage`는 자신의 `return`으로 JSX를 반환하고, 수량 변경 함수는 상태를 갱신한다.
- 장바구니 목록을 하나의 공통 상태로 관리하면 Cart와 Header가 같은 변경 결과를 읽을 수 있다. 상품금액과 수량 합계는 그 목록으로부터 계산한다.

### 핵심 코드

아래는 실제 `CartPage` 내부의 수량 증가 로직이다. 들여쓰기와 주석 배치를 정리한 발췌이며, 별도 예제 기능을 추가한 코드는 아니다.

```tsx
function handleIncreaseQuantity(cartItemId: number) {
    // 연속 클릭에도 직전 상태를 기준으로 수량을 계산한다.
    setCartItems((previousItems) =>
        previousItems.map((item) =>
            item.id === cartItemId
                ? { ...item, quantity: item.quantity + 1 }
                : item,
        ),
    );
}
```

여기서 `map` 콜백의 반환값은 상품 객체이고, `map`의 반환값은 새 상품 배열이다. 이 배열을 상태 갱신에 사용한다. `handleIncreaseQuantity` 자체는 화면용 JSX를 반환하지 않는다.

아래 JSX는 `CartPage`의 최상위 `return` 내부에서 발췌했다. 위 함수만 정의해 놓는 것으로 끝나지 않고, 자식 컴포넌트에 이벤트 함수를 전달해야 한다.

```tsx
<CartItemList
    items={cartItems}
    onIncreaseQuantity={handleIncreaseQuantity}
    onDecreaseQuantity={handleDecreaseQuantity}
    onRemoveItem={handleRemoveItem}
/>

{cartItems.length > 0 && <CartSummary items={cartItems} />}
```

`CartItemList`에서는 증가 버튼에 다음처럼 연결한다.

```tsx
onClick={() => onIncreaseQuantity(item.id)}
```

### 오늘 수행한 실습

- 상품 목록·이미지·옵션·단가를 표시하고, 수량 증가·감소와 개별 삭제를 연결했다.
- 최소 수량 1개를 유지하고, 마지막 상품을 삭제하면 빈 장바구니 안내를 표시하도록 구성했다.
- 주문 요약에 상품금액 합계를 표시하고, 빈 장바구니에서는 주문 요약을 숨겼다.
- `계속 쇼핑하기`를 상품 목록에 연결하고, Cart와 Header의 수량을 Zustand 상태로 연결했다.
- Cart와 주문 요약의 배치·간격을 조절하고, CHECKOUT 버튼은 UI까지만 준비했다.

## 2. Why — 왜 필요한가?

### 이 개념이 필요한 이유

화면에 보이는 JSX, 클릭했을 때 실행되는 함수, 상품 데이터를 저장하는 상태가 섞여 보이면 코드를 어느 파일의 어느 위치에 넣을지 판단하기 어렵다. 화면을 그리는 책임과 상태를 바꾸는 책임을 나누어 보면, 오류가 발생했을 때 확인할 위치도 좁힐 수 있다.

### 내 생각

오늘은 힘들었다. 코드를 작성하면서 React의 폴더와 파일 구조까지 함께 이해하려고 하니 예상보다 시간이 오래 걸렸다. 특히 `page.tsx` 안에 함수가 여러 개 있는데도 화면이 어떻게 나오는지 이해하기 어려웠다.

수량을 바꾸는 함수와 화면을 반환하는 부분이 각각 맡는 역할을 연결해서 보니 신기했다. 함수가 여러 개 있다는 것보다, **어떤 함수가 실행되고 어떤 상태가 바뀌며 그 상태를 JSX가 어떻게 사용하는지**가 중요하다는 점을 배웠다. 다음에는 코드를 붙일 위치만 찾는 데서 그치지 않고, 그 위치에 있어야 하는 이유도 함께 확인하고 싶다.

## 3. How — 어떻게 작동하는가?

### 작동 과정

1. `CartPage`가 공통 상태의 `cartItems`를 읽고, 자신의 최상위 `return`에서 목록과 요약을 조합한다.
2. `CartItemList`의 증가 버튼을 클릭하면 전달받은 함수에 해당 상품의 `id`를 넘긴다.
3. `handleIncreaseQuantity`는 이전 상품 배열을 기준으로 선택한 상품의 수량만 변경한 새 배열을 만든다.
4. `setCartItems`가 Zustand의 상품 목록을 갱신한다.
5. 변경된 목록을 구독하는 `CartPage`와 수량 합계를 구독하는 `Header`가 다시 렌더링된다. 자식 목록과 요약에도 최신 데이터가 전달된다.
6. React가 새 렌더링 결과를 반영하여 수량·금액·Header 표시가 달라진다. 다시 렌더링한다고 모든 DOM을 통째로 교체하는 것은 아니다.

### 내 말로 설명하기

오늘 이해한 내용을 정리하면, `page.tsx` 안의 여러 함수는 서로 다른 일을 맡는다. 증가·감소·삭제 함수는 버튼을 눌렀을 때 데이터를 바꾸고, `CartPage`의 `return`은 현재 데이터를 어떤 화면으로 보여줄지 정한다.

같은 `map`이어도 사용하는 위치를 봐야 한다. 상태 갱신 안의 `map`은 새 데이터 배열을 만들고, JSX 안에서 `<li>`를 반환하는 `map`은 표시할 요소 목록을 만든다.

## 5. 오늘의 문제 해결

### 문제 상황

Cart에서 수량을 늘리면 상품 수량과 금액은 변했지만 Header의 CART 수량은 바뀌지 않았다. 별도로 Header에서 상태 훅을 사용하면서 다음 런타임 오류도 만났다.

```text
useSyncExternalStore only works in Client Components.
```

### 문제가 발생한 구조

- Cart는 자신의 로컬 상품 상태를 변경하고, Header는 별도의 숫자 상태 또는 고정 표시를 사용하고 있었다.
- Header에서 Zustand 훅을 호출했지만 Client Component 경계가 설정되지 않았다.

### 문제의 원인

수량 불일치의 직접 원인은 같은 정보를 표현하는 두 화면이 서로 다른 상태를 읽는 것이었다. 런타임 오류의 직접 원인은 클라이언트 훅을 사용하는 Header의 컴포넌트 경계였다. 서로 다른 원인을 각각 수정해야 했다.

### 해결한 코드

Header의 파일 맨 위에 정확한 `'use client';` 지시문을 두고, 공통 상품 목록에서 수량 합계를 계산하도록 연결했다. 아래는 Header 내부의 실제 계산 로직이다.

```tsx
const totalQuantity = useCounterStore((state) =>
    state.cartItems.reduce((total, item) => total + item.quantity, 0),
);
```

### 해결 원리와 재실행 결과

Cart와 Header가 같은 상품 목록을 사용하므로 따로 숫자를 맞추는 작업이 필요하지 않다. Header의 숫자는 상품 종류 수가 아니라 각 상품 수량의 합이다. 증가·감소·삭제를 다시 확인했을 때 Header는 `2 → 3 → 2 → 1 → 0`으로 일치했다.

`setCartItems`를 사용하는 감소 함수를 `CartPage` 밖에 놓았을 때의 범위 오류도 있었다. 함수 위치를 컴포넌트 안으로 옮겨, 같은 범위에서 갱신 함수에 접근하도록 수정했다. 코드를 추가할 때 중괄호와 함수 경계를 먼저 확인해야 하는 이유를 배웠다.

### Keep — 계속할 것

- 코드를 직접 작성하고, 이해되지 않는 함수·파일·JSX 위치를 작게 나누어 확인했다.
- 코드 변경 뒤 실제 버튼을 눌러 수량·금액·Header가 함께 달라지는지 확인하는 방식을 유지한다.

### Problem — 개선할 것

- 폴더·파일 역할과 React 실행 흐름을 동시에 이해해야 해서 작업 시간이 길어졌다.
- 코드를 어디에 넣는지 찾다가 함수와 JSX의 경계를 놓치거나 기존 표시를 중복으로 남기는 일이 있었다.
- 오늘의 이해를 예제 없이 다시 작성할 수 있는지는 아직 확인하지 않았다.
- 팀 저장소의 여러 규칙을 동시에 지키면서 main·dev에 잘못 병합할까 봐 긴장했다.

### Try — 다음에 시도할 것

- 코드를 수정하기 전에 해당 파일이 맡는 일을 한 문장으로 적는다.
- 수량 증가 흐름 하나를 버튼 → 함수 → 상태 → JSX 순서로 따라가 본다.
- 기능 하나를 연결한 뒤에는 화면을 확인하고, 여러 변경을 한꺼번에 쌓지 않는다.
- Git 작업 전 현재 브랜치와 PR 대상·변경 범위를 확인하고, 리뷰와 병합을 별개로 확인한다.

## 8. 이해도 점검

오늘은 이해가 달라진 지점을 회고했으며, 별도의 이해도 평가를 진행하지 않아 아래 항목을 선택하지 않았다.

- [ ] 오늘 발생한 오류의 원인을 설명할 수 있다.

## STAR 문제 해결 기록

### Situation — 상황

Cart를 개발하면서 페이지·도메인 컴포넌트·공통 상태의 역할을 동시에 이해해야 했다. `page.tsx` 안에 여러 함수가 있을 때 화면이 어떻게 결정되는지가 특히 어려웠다.

### Task — 해결 과제

수량 증가·감소·삭제 함수와 화면 반환의 역할을 구분하고, Cart와 Header가 같은 장바구니 변경을 보여주게 해야 했다.

### Action — 실행한 행동

1. 각 파일과 함수가 맡는 역할을 확인하고, 이벤트 함수를 `CartPage` 안의 적절한 위치에 두었다.
2. 자식 컴포넌트에 이벤트 함수를 Props로 전달하고, 버튼에서 상품 `id`와 함께 호출하도록 연결했다.
3. 상품 목록을 공통 상태로 옮기고 합계·수량을 그 목록에서 계산하도록 수정했다.
4. 실제 화면의 증가·감소·삭제·빈 상태를 확인하고 코드와 결과를 대조했다.

### Result — 결과

- Cart의 수량·금액과 Header 수량이 함께 변경되는 흐름을 확인했다.
- 이벤트 함수의 반환값과 컴포넌트의 JSX 반환을 구분하는 관점을 얻었다. 처음에는 오래 걸렸지만, 각각의 역할이 연결되어 화면이 바뀐다는 점을 이해한 것이 오늘 가장 기억에 남는다.
- 리뷰 승인을 1건 받았으나 Draft PR은 아직 병합하지 않았다. 전체 빌드와 남은 공통 화면 문제까지 해결된 상태는 아니다.
