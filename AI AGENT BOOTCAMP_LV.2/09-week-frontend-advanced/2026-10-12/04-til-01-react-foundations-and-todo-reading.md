# TIL | 2026-10-12 | React 기초와 Todo 코드 읽기

> **React가 화면을 작은 컴포넌트로 조립하는 실용적인 도구라는 점은 알겠지만, 함수에서 Hook까지 개념이 빠르게 확장되어 어렵게 느껴졌다.**

> 입력 이벤트가 함수를 실행하고, 함수가 상태 변경을 요청하면 React가 화면을 다시 계산한다는 하나의 흐름으로 연결하기 시작했다.

- Level / Week: LV.2 / Week 9
- 과정: 프론트엔드 응용 (React/Next.js)

---

## 1. What — 무엇을 배웠는가?

### 핵심 개념

- React는 웹 화면을 작은 컴포넌트로 나누어 조립하고, 데이터 변화에 따라 화면을 다시 계산하는 JavaScript 라이브러리다.
- `.tsx`는 TypeScript와 JSX 화면 문법을 함께 사용하는 파일이다.
- Fragment `<>...</>`는 실제 HTML 태그를 추가하지 않고 여러 요소를 묶는다.
- `const`와 `let`은 프로그램 실행 중 같은 이름에 값을 다시 할당하는지에 따라 구분한다.
- Hook은 함수 컴포넌트에서 상태와 실행 시점 같은 React 기능을 사용하는 함수다.
- `useState`는 바뀌는 데이터를 기억하고 화면 갱신을 요청한다.
- `useCallback`은 필요한 경우 같은 함수 참조를 재사용하지만 모든 함수에 붙일 필요는 없다.

### 핵심 코드

```tsx
interface Todo {
  id?: number;
  title: string;
  checked: boolean;
}

const [form, setForm] = useState<Todo>({
  title: '',
  checked: false,
});

const onChange = (event: React.ChangeEvent<HTMLInputElement>) => {
  setForm({ ...form, title: event.target.value });
};
```

위 코드는 Todo 데이터의 모양을 정하고, 입력값이 바뀔 때 새로운 `form` 상태를 React에 전달하는 흐름을 보여준다. 오늘은 코드의 의미를 읽었으며 직접 실행 결과는 확인하지 않았다.

### 오늘 수행한 실습

- `TodoPage` 코드를 위에서 아래로 읽으며 인터페이스, 상태, 입력 이벤트 함수의 역할을 구분했다.
- `useState<Todo>({})`에는 필수인 `title`과 `checked` 초기값이 없다는 점을 확인했다.
- `onSubmit`이 비어 있고 `<form>`에 연결되지 않아 등록 기능이 완성되지 않았다는 점을 확인했다.
- `items` 배열을 `TodoItem`으로 출력하는 목록 렌더링이 아직 없다는 점을 확인했다.
- 코드를 수정하거나 실행해 Todo 등록 성공을 확인하지는 않았다.

## 2. Why — 왜 필요한가?

### 이 개념이 필요한 이유

- 상품 카드, 장바구니 버튼과 메뉴를 컴포넌트로 나누면 화면을 재사용하고 관리하기 쉽다.
- 사용자가 입력하거나 클릭했을 때 상태를 변경하면 React가 바뀐 데이터를 화면에 반영할 수 있다.
- 함수, 이벤트, 상태와 렌더링의 관계를 이해해야 쇼핑몰 기능을 작은 단위로 구현할 수 있다.
- 기본 흐름을 이해하지 않고 Hook과 최적화 기능을 한꺼번에 사용하면 코드가 왜 작동하는지 추적하기 어렵다.

### 내 생각

> React의 실용성은 알겠지만 Python 기초에서 시작한 변수와 함수가 JavaScript의 함수·콜백·클래스, 다시 React의 컴포넌트·Hook·상태로 확장되면서 개념들이 섞이는 느낌이 든다. 특히 함수 부분이 약하다고 느끼는 상태에서 바로 쇼핑몰 프로젝트가 시작되어 막막하다.

---

## 3. How — 어떻게 작동하는가?

### 작동 과정

1. 사용자가 입력창에 글자를 입력한다.
2. `onChange` 이벤트 함수가 실행된다.
3. 함수가 `setForm()`으로 새로운 상태를 전달한다.
4. React가 컴포넌트를 다시 실행한다.
5. 새로운 `form.title`이 입력창에 표시된다.

### 내 말로 설명하기

> React에서는 화면을 직접 하나씩 고치는 대신 바뀐 데이터를 알려준다. 사용자의 입력이 함수를 실행하고, 그 함수가 상태를 바꾸면 React가 새로운 상태에 맞는 화면을 다시 만들어 준다.

## 5. KPT 회고

### Keep — 계속할 것

- 오늘 잘한 점: 모르는 용어를 넘기지 않고 Fragment, Hook, `const`, `useCallback`의 뜻을 하나씩 질문했다.
- 계속 유지할 학습 방법: 코드를 위에서 아래로 한 줄씩 읽고 `입력 → 실행 함수 → 상태 → 화면` 순서로 연결한다.

### Problem — 개선할 것

- 이해하기 어려웠던 부분: 함수, 콜백, 클래스, 컴포넌트와 Hook의 역할이 한꺼번에 섞였다.
- 반복해서 실수한 부분: 아직 직접 코드를 실행하지 않아 반복 실수 여부는 확인하지 못했다.
- 아직 설명하기 어려운 부분: 함수 호출부터 상태 변경과 다시 렌더링까지의 전체 실행 흐름이다.

### Try — 다음에 시도할 것

- 다시 공부할 내용: 일반 함수의 정의·호출·인수·반환과 이벤트 함수의 관계.
- 예제를 보지 않고 작성해볼 코드: 상품 정보를 Props로 받는 상품 카드 컴포넌트 한 개.
- 다음 학습에서 바꿔볼 방법: 쇼핑몰 전체를 한 번에 만들지 않고 상품 카드 → 목록 → 장바구니 상태 순서로 확장한다.
