## 2. Why — 왜 필요한가?

### 이번 주 핵심 개념이 필요한 이유

Python 문법을 배우는 목적은 단순히 코드를 외우는 것이 아니라 프로그램이 어떤 순서와 구조로 동작하는지 이해하기 위해서다.

`if`는 상황에 따라 다른 동작을 선택하고, `for`는 반복되는 작업을 처리하며, 함수는 하나의 동작을 묶어서 다시 사용할 수 있게 한다.

이번 주 후반에 배운 표준 라이브러리와 `import`를 보면서 모든 기능을 직접 처음부터 만드는 것이 아니라 이미 만들어진 기능을 가져와서 새로운 문제를 해결할 수 있다는 것도 알게 되었다.

Git과 GitHub 역시 단순히 파일을 올리는 도구가 아니라 내가 무엇을 공부했고, 어떤 문제를 겪었고, 어떻게 발전했는지를 보여주는 기록 도구가 될 수 있다고 느꼈다.

### 내 생각

> 이번 주 취업지원 세션에서 가장 기억에 남은 메시지는 세 가지였다.
>
> 1. 잘 기록하고
> 2. 공유하고
> 3. 진화를 보여줘라.
>
> 이 말을 들으면서 내가 왜 이 부트캠프에 왔는지를 다시 생각하게 됐다.
>
> 단순히 새로운 기술을 배우는 것에서 끝나는 것이 아니라, 그동안 쌓아온 경험과 지식을 다시 리뷰하고 나의 강점과 약점을 정리해서 GitHub와 Notion 등에 기록하고 공유해야겠다고 생각했다.
>
> 앞으로 중요한 것은 '무엇을 알고 있다'만 보여주는 것이 아니라, 처음에는 무엇을 몰랐고 어떤 시행착오를 거쳐 어떻게 나아졌는지를 보여주는 것이라고 느꼈다.

## 3. How — 어떻게 작동하는가?

### 핵심 작동 과정

1. Python의 기본 문법을 이용해 프로그램의 흐름을 만든다.
2. 반복되는 동작을 함수 등으로 묶고 기존에 만들어진 기능을 가져와 조합한다.
3. 실습 과정과 시행착오를 Git과 GitHub에 기록하면서 나의 학습 과정을 남긴다.

### 개념 사이의 연결

> 아직 Python 개념들이 완전히 연결되어 있지는 않다.
>
> `if`와 `for`는 이전보다 조금 익숙해졌지만 함수부터 다시 어려움이 커졌다.
>
> 함수에 대한 이해가 충분하지 않은 상태에서 iterator, generator, 모듈과 같은 새로운 개념이 이어지면서 머릿속에서 개념들이 서로 섞이기 시작했다.
>
> 지금은 새로운 내용을 더 많이 외우기보다 기초 개념부터 다시 연결하는 과정이 필요하다.

### 내 말로 설명하기

> Python을 배우면서 단순히 문법을 외우는 것이 아니라 개발자가 문제를 어떻게 나누고, 반복되는 부분을 어떻게 묶고, 기존에 존재하는 기능을 어떻게 활용하는지를 조금씩 보고 있는 것 같다.
>
> 아직 그 사고방식이 내 것이 되지는 않았다.
>
> 오히려 지금까지 익숙했던 일하는 방식과 다른 사고방식을 나한테 직접 이식하는 것 같은 지각변동을 겪고 있다는 느낌이 든다.
>
> 그래서 힘들지만 앞으로 어떻게 달라질지 기대되기도 한다.

## 4. 이번 주 가장 중요했던 문제 해결

> 이번 주의 가장 중요한 문제는 특정 코드 오류 하나가 아니라, 학습 내용을 따라가면서도 내가 실제로 무엇을 이해하고 있는지 구분하지 못하고 있었다는 점이다.

### 문제 상황

- 하려고 했던 것:
  - Python 수업을 따라가고 학습 자료를 체계적으로 관리하기
  - GitHub, Notion, Slack 등을 이용해 혼자서도 학습 기록 구조 만들기

- 발생한 문제:
  - Python 함수부터 개념 이해가 크게 어려워졌다.
  - 수업 코드는 따라 작성하지만 혼자 설명하거나 작성하기 어렵다.
  - 회사에서 사용했던 것처럼 GitHub, Notion, Slack을 개인적으로도 쉽게 설계할 수 있을 것이라고 생각했지만 실제로 직접 구조를 만들려고 하니 어려웠다.

### 문제의 원인

- 회사에서는 이미 잘 설계된 업무 구조 안에서 도구를 사용하고 있었다.
- 내가 직접 정보 구조와 기록 기준을 처음부터 설계해본 경험은 생각보다 적었다.
- Python에서도 코드를 따라가는 것과 개념을 이해해 직접 설명하는 것은 다른 문제였다.

### 해결 원리

> 우선 현재 부족한 부분을 인정하고 기초로 돌아가기로 했다.
>
> 동시에 모든 자료를 완벽하게 정리하려고 하기보다는 실제 학습에 필요한 최소한의 구조부터 만들기로 했다.
>
> 앞으로는 수업 내용 자체는 AX_study에 기록하고, 내가 무엇을 이해하지 못했고 어떻게 해결했는지는 Blast-Forge-Lab에 남기면서 변화 과정을 기록하려고 한다.

### 이 문제에서 배운 점

- 도구를 사용할 줄 아는 것과 구조를 설계할 줄 아는 것은 다른 능력이다.
- 예제를 따라 작성할 수 있는 것과 개념을 이해한 것은 다르다.
- 현재 부족한 점을 정확하게 발견하는 것도 학습 과정의 일부다.
- 기록은 완성된 모습을 보여주는 용도뿐 아니라 변화 과정을 보여주는 자료가 될 수 있다.

### 이제 이해한 내용

| 개념 | 이전 생각 | 지금 이해한 내용 |
| --- | --- | --- |
| Git / GitHub | 사용법 자체도 낯설었다. | 2주 전보다 기본적인 사용 흐름이 익숙해졌다. |
| `if` | 조건문이 어렵고 낯설었다. | 아직 부족하지만 조건에 따라 동작을 나눈다는 기본 구조가 조금 익숙해졌다. |
| `for` | 반복문 자체가 낯설었다. | 반복되는 값을 하나씩 처리한다는 감각이 조금 생겼다. |

### 아직 헷갈리는 내용

| 개념 | 헷갈리는 부분 | 다음에 확인할 것 |
| --- | --- | --- |
| 함수 | 함수의 전체 구조와 작동 원리를 내 말로 설명하기 어렵다. | 매개변수, 반환값, 함수 호출부터 기본 예제로 다시 확인 |
| Iterable / Iterator | 둘의 관계가 머릿속에서 섞여 있다. | `iter()`와 `next()`를 직접 실행하며 비교 |

| `import` / `from` / `as` | 가져오는 대상과 호출 방식이 혼란스럽다. | 같은 모듈을 세 가지 방법으로 직접 가져와 비교 |
| `datetime` | 이전에도 배웠지만 코드 구조가 여전히 어렵다. | 최소 예제부터 직접 실행 |
