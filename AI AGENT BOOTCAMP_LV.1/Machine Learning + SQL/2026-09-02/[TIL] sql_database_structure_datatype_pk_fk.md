# TIL | 2026-09-02 | SQL 기초와 데이터베이스 구조

> DB, DBMS, RDBMS의 차이와 테이블 구조, 데이터 타입, PK/FK의 기본 개념을 처음부터 연결해서 이해했다.

---

## 1. What — 무엇을 배웠는가?

### 핵심 개념

- **DB(Database)**: 체계적으로 저장된 데이터의 집합
- **DBMS(Database Management System)**: DB를 생성·운영·관리하는 소프트웨어
- **RDBMS(Relational DBMS)**: 데이터를 테이블 형태로 저장하고 테이블 간 관계를 통해 관리하는 DBMS
- **PostgreSQL**: 대표적인 RDBMS 중 하나
- **SQL**: 데이터베이스에 질문하거나 명령하기 위한 표준 언어

### 데이터베이스 구조

- **Table**: 데이터를 행과 열 형태로 저장하는 구조
- **Row / Record**: 하나의 데이터 항목
- **Column / Field**: 데이터의 속성
- **Cell**: 행과 열이 만나는 하나의 실제 값
- **Schema**: 테이블, 컬럼, 데이터 타입, 제약조건 등의 구조를 정의한 설계 명세

### 데이터 타입

#### 숫자형
- `SMALLINT`
- `INT`
- `BIGINT`
- `REAL`
- `DOUBLE PRECISION`
- `DECIMAL(P, S)`

#### 문자형
- `CHARACTER`
- `VARCHAR`
- `TEXT`

#### 논리형
- `BOOLEAN`
  - `TRUE`
  - `FALSE`
  - `NULL`은 값이 없거나 알 수 없는 상태

#### 날짜와 시간
- `DATE`
- `TIME`
- `TIMESTAMP`
- `TIMESTAMPTZ`

#### 기타
- `JSON`
- `JSONB`
- `ENUM`
- `VECTOR`

### PK / FK

- **PK(Primary Key)**
  - 각 행을 고유하게 식별하는 키
  - 중복 불가
  - NULL 불가

- **FK(Foreign Key)**
  - 다른 테이블의 PK를 참조하는 키
  - 테이블 간 관계를 연결하는 역할

### 데이터 무결성

- **도메인 무결성**: 컬럼에 허용된 데이터 타입과 값의 범위를 지켜야 함
- **개체 무결성**: PK는 중복되거나 NULL일 수 없음
- **참조 무결성**: FK가 참조하는 값은 참조 대상 테이블에 실제로 존재해야 함

### 오늘 수행한 실습

- ERDCloud에서 테이블 구조 설계
- Logical Name과 Physical Name 구분
- 회원 정보 컬럼의 Physical Name과 데이터 타입 설계
  - 이름: `name` / `VARCHAR(50)`
  - 휴대전화번호: `phone` / `VARCHAR(20)`
  - 이메일: `email` / `VARCHAR(100)`
  - 성별: `gender` / `VARCHAR(10)` 또는 `ENUM`
  - 주소: `address` / `VARCHAR(255)`
  - 우편번호: `postal_code` / `VARCHAR(10)`
  - 가입일: `created_at` / `DATE` 또는 `TIMESTAMP`

> 오늘은 SQL 명령어 작성 및 실행은 아직 시작하지 않았다.

## 2. Why — 왜 필요한가?

### 이 개념이 필요한 이유

- SQL을 작성하기 전에 데이터가 어떤 구조로 저장되는지 이해해야 한다.
- DB와 DBMS를 구분해야 PostgreSQL이 어떤 역할을 하는지 이해할 수 있다.
- 테이블의 행, 열, PK, FK 구조를 알아야 이후 여러 테이블을 연결해서 조회할 수 있다.
- 데이터 타입과 무결성 규칙을 설정하면 잘못된 데이터가 저장되는 것을 방지할 수 있다.
- 스키마를 이해해야 실제 데이터베이스를 만들기 전에 구조를 설계할 수 있다.

### 내 생각

> 예전에 BigQuery에서 쿼리를 사용한 경험은 있었지만, SQL 아래에 DB → DBMS → RDBMS → 테이블이라는 구조가 있다는 것은 제대로 구분하지 않고 사용했던 것 같다. 이번에는 SQL 문법부터 외우기보다 데이터가 실제로 어디에 저장되고 PostgreSQL이 어떤 역할을 하는지부터 구조적으로 이해하는 과정이라는 점이 새로웠다.

## 3. How — 어떻게 작동하는가?

### 작동 과정

1. 데이터는 데이터베이스에 저장된다.
2. PostgreSQL 같은 DBMS가 데이터베이스를 생성하고 관리한다.
3. RDBMS에서는 데이터를 테이블의 행과 열 구조로 저장한다.
4. 각 테이블의 PK가 행을 고유하게 구분한다.
5. 다른 테이블의 FK가 PK를 참조하면서 테이블 사이의 관계가 만들어진다.
6. 이후 사용자는 SQL을 통해 DBMS에 데이터 조회·수정 등의 명령을 전달한다.

### 내 말로 설명하기

> DB는 데이터가 모여 있는 곳이고, DBMS는 그 데이터를 관리하는 프로그램이다. PostgreSQL은 DBMS 중에서도 테이블 관계를 이용하는 RDBMS이다. 데이터는 테이블 안에 행과 열 형태로 저장되고, PK로 각각의 데이터를 구분한다. 다른 테이블에서는 FK를 이용해 그 PK를 참조하면서 데이터끼리 관계를 만든다.

## 4. 오늘의 문제 해결

### 문제 상황

- 하려고 했던 것: Docker Desktop을 실행하여 이후 PostgreSQL 실습 환경을 준비하려고 했다.
- 발생한 문제: Docker Desktop에서 가상화 지원을 감지하지 못했다는 오류가 발생했다.
- 확인 결과: BIOS 가상화는 활성화되어 있었지만 WSL이 설치되어 있지 않았고, 이후 WSL2 실행에 필요한 Virtual Machine Platform 설정을 확인했다.

### 오류 메시지

```text
Virtualization support not detected

Docker Desktop failed to start because virtualisation support wasn’t detected.
```

### 문제의 원인

- CPU 가상화 기능 자체는 활성화되어 있었다.
- Windows에서 WSL이 설치되어 있지 않았고, WSL2 실행에 필요한 Virtual Machine Platform 구성이 완료되지 않은 상태였다.

### 해결 과정

1. 작업 관리자에서 CPU 가상화가 `사용` 상태인지 확인했다.
2. PowerShell에서 `wsl --status`, `wsl --version`으로 상태를 확인했다.
3. WSL을 설치했다.
4. WSL2 및 Virtual Machine Platform 설정을 확인했다.

### 해결 원리

> Docker Desktop이 Windows에서 Linux 기반 컨테이너를 실행하기 위해서는 WSL2와 가상화 기능이 필요하다. 단순히 Docker를 다시 설치하는 것이 아니라 Docker 아래에서 필요한 실행 환경이 준비되어 있는지를 확인해야 한다는 것을 알게 되었다.
