# TIL | 2026-08-18 | Python Class 첫 학습

> **객체·함수·메서드·변수가 한꺼번에 뒤섞인 카오스 속에서, Class가 속성과 기능을 정리하는 설계도라는 것까지 이해했다.**

> 클래스를 배우면서 문법을 외우는 것보다 객체·클래스·함수·변수 사이의 관계를 반복해서 사용하며 이해하는 것이 중요하다는 것을 느꼈다.

---

## 1. What — 무엇을 배웠는가?

### 핵심 개념

- `class`는 여러 데이터의 **속성과 기능을 하나의 구조로 정리하는 설계도**와 같은 개념이다.
- 클래스 안에 정의된 함수는 **메서드(Method)** 로 사용할 수 있다.
- `__init__()`은 객체가 생성될 때 초기 상태를 설정하는 데 사용한다.
- `self`는 클래스에서 현재 객체를 가리킬 때 관례적으로 사용하는 이름이며, `self`라는 이름 자체가 반드시 강제되는 것은 아니다.
- 클래스의 기본적인 구조는 이해했지만 객체, 클래스, 함수, 메서드, 변수, 속성의 관계는 아직 명확하게 구분하기 어렵다.

### 핵심 코드

```python
class Person:
    def __init__(self, name):
        self.name = name
```

현재는 위 코드의 **형태는 따라 작성할 수 있지만**, 각 요소가 서로 어떤 관계인지 완전히 설명하기는 어렵다.

특히 아직 헷갈리는 것은 다음과 같다.

- `Person`과 실제 생성되는 객체의 관계
- `__init__()`이 정확히 어떤 역할을 하는지
- `self`가 실제로 무엇을 가리키는지
- `name`과 `self.name`의 차이
- 함수가 언제 메서드라고 불리는지

### 오늘 수행한 실습

- 처음으로 `class`를 선언했다.
- `__init__(self, ...)` 형태로 초기화 메서드를 작성했다.
- 클래스 내부에 함수를 정의하는 구조를 실습했다.
- 예제를 보면서 클래스의 기본 구조를 따라 작성했다.
- 혼자서 처음부터 클래스를 설계하고 작성하는 것은 아직 어려웠다.

---

## 2. Why — 왜 필요한가?

### 이 개념이 필요한 이유

- 서로 관련된 데이터와 기능을 하나의 구조 안에서 관리할 수 있다.
- 변수와 함수를 각각 따로 관리하는 것보다 관련 있는 요소를 묶어서 표현할 수 있다.
- 데이터가 많아지고 기능이 복잡해질수록 구조를 정리하는 데 도움이 될 것 같다.

### 내 생각

> 지금은 클래스가 왜 필요한지를 프로그램 수준에서 완전히 이해하지는 못했다.
>
> 하지만 지금까지 변수와 함수를 따로 배웠다면, 클래스에서는 이 요소들이 하나의 관계 안에 묶이기 시작한다는 느낌을 받았다.
>
> 결국 Class는 여러 데이터의 속성과 기능을 정리한 **설계도** 같은 것이라고 이해하고 있다.

---

## 3. How — 어떻게 작동하는가?

### 작동 과정

1. `class`를 사용해서 클래스의 구조를 만든다.
2. `__init__()`을 정의해서 객체가 처음 만들어질 때 필요한 값을 설정한다.
3. 클래스 안에 필요한 기능을 함수 형태로 정의하고 메서드로 사용한다.
4. 클래스를 바탕으로 객체를 만들고, 객체가 가진 속성과 메서드를 사용한다.

### 내 말로 설명하기

> 클래스는 어떤 데이터를 가지고 어떤 기능을 수행할지를 미리 정리해두는 설계도라고 생각한다.
>
> 그 설계도를 바탕으로 실제 객체를 만들 수 있고, 객체는 클래스에서 정의한 속성과 기능을 사용할 수 있다.
>
> 아직 객체와 클래스의 관계를 정확하게 설명하기는 어렵지만, 적어도 클래스를 단순히 새로운 문법 하나로 외우는 방식으로는 제대로 이해할 수 없다는 점은 알게 되었다.
>
> 반복해서 직접 사용하면서 객체, 함수, 변수, 클래스가 서로 어떻게 연결되는지를 정리해야 할 것 같다.

## 5. KPT 회고

### Keep — 계속할 것

- 오늘 잘한 점:
  - 이해되지 않는 개념을 억지로 이해했다고 넘기지 않고, 무엇이 혼란스러운지 구분하려고 했다.
  - 클래스가 **속성과 기능을 정리하는 설계도**라는 핵심 개념까지는 잡았다.

- 계속 유지할 학습 방법:
  - 예제를 통해 구조를 먼저 확인한다.
  - 문법만 외우지 않고 각 요소가 왜 필요한지 계속 질문한다.
  - 이해되지 않는 개념은 반복해서 직접 사용해본다.

### Problem — 개선할 것

- 이해하기 어려웠던 부분:
  - 객체, 클래스, 함수, 메서드, 변수, 속성의 관계가 한꺼번에 섞였다.
  - `self`가 무엇을 의미하는지 아직 직관적으로 이해되지 않는다.
  - 예제를 보면 이해되지만 원론적으로 설명하려고 하면 다시 혼란스러워진다.

- 반복해서 실수한 부분:
  - 클래스 안으로 코드 구조가 깊어지면서 들여쓰기가 계속 신경 쓰인다.
  - 들여쓰기를 잘못해서 오류가 발생할까 봐 아직 부담을 느낀다.

- 아직 설명하기 어려운 부분:
  - 클래스와 객체의 정확한 차이
  - 함수와 메서드의 차이
  - `self`가 필요한 이유
  - `name`과 `self.name`의 차이
  - `__init__()`이 호출되는 과정

### Try — 다음에 시도할 것

- 다시 공부할 내용:
  - 클래스 → 객체 → 속성 → 메서드의 관계
  - `self`의 의미
  - `__init__()`의 역할

- 예제를 보지 않고 작성해볼 코드:
  - 이름 하나만 저장하는 아주 작은 클래스
  - 속성 1~2개와 메서드 하나를 가진 클래스

- 다음 학습에서 바꿔볼 방법:
  - 완성된 예제를 따라 쓰는 것에서 끝내지 않고 같은 구조를 직접 다시 작성해본다.
  - 한 번에 모든 개념을 이해하려 하기보다 클래스 → 객체 → 속성 → 메서드를 하나씩 연결해서 본다.
  - 코드의 들여쓰기 구조를 눈으로 확인하면서 작성한다.
