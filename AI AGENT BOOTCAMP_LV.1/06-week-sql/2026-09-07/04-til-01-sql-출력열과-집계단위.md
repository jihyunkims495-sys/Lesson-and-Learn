# TIL — SQL 조회 결과의 출력 열과 집계 단위

> 학습 날짜: 2026-09-07
> 학습 범위: SQL 조회·집계·테이블 결합의 전체 흐름과 기초 복습

## 오늘 학습한 흐름

SQL로 데이터를 다룰 때는 문법부터 쓰기 전에 결과의 모습을 먼저 정해야 한다.

```text
조건에 맞는 행 선택
→ 결과에 보여 줄 열 선택
→ 여러 행을 기준별로 묶어 요약
→ 필요한 경우 다른 테이블의 정보 연결
```

오늘은 작은 고객 표를 이용해 조건에 맞는 행을 고르고, 조건 판단에 사용하는 열과 실제 출력 열을 구분하는 연습을 했다. 이어서 일반 고객 목록과 도시별 고객 수 집계 결과에서 한 행이 뜻하는 대상이 달라진다는 설명을 확인했다.

## 조건에 사용하는 열과 출력할 열은 다를 수 있다

“서울에 사는 고객의 이름만 조회한다”는 문제는 두 판단으로 나뉜다.

1. `city`를 이용해 서울 고객만 남긴다.
2. 결과에는 요구된 `customer_name`만 보여 준다.

`city`는 어떤 행을 남길지 판단하는 조건 열이지만, 문제에서 이름만 요구했다면 반드시 출력할 필요는 없다. SQL을 작성하기 전 다음 두 질문을 따로 확인하는 것이 중요하다.

```text
어떤 행을 남길 것인가?
어떤 열을 보여 줄 것인가?
```

## 집계하면 결과 한 행의 의미가 바뀐다

집계하지 않은 고객 목록에서는 한 행이 고객 한 명을 뜻한다. 반면 도시별 고객 수를 집계한 결과에서는 한 행이 도시 하나와 그 도시에 속한 고객 수를 뜻한다.

```text
고객 목록의 한 행
→ 고객 한 명

도시별 고객 수의 한 행
→ 도시 하나와 해당 도시의 고객 수
```

따라서 `GROUP BY`와 집계함수를 사용할 때는 SQL 문법을 쓰기 전에 “결과 한 행은 무엇을 의미하는가?”를 먼저 설명해야 한다.

## 오늘 확인한 내용과 아직 확인하지 않은 내용

확인한 내용:

- 작은 표에서 서울이라는 조건에 맞는 고객을 선택했다.
- 조건 판단에 사용하는 열과 결과에 출력하는 열이 다를 수 있음을 확인했다.
- 일반 목록과 집계 결과에서 한 행의 의미가 달라진다는 설명을 들었다.

아직 확인하지 않은 내용:

- 실제 SQL 작성과 데이터베이스 실행
- 집계 결과의 한 행 의미를 새로운 문제에서 직접 설명하는 것
- `WHERE`와 `HAVING`의 구분
- `JOIN` 종류와 JOIN 후 행 수 변화
- 서브쿼리, 인라인 뷰, 스칼라 서브쿼리
