# TIL | 2026-08-20 | Python 내장 함수와 표준 라이브러리

> 오늘은 직접 반복문과 조건문을 길게 작성하지 않아도 Python이 이미 제공하는 내장 함수와 표준 라이브러리를 조합해서 데이터를 검사하고, 계산하고, 변환하고, 시간·파일·난수 같은 기능까지 처리할 수 있다는 것을 배웠다. 함수 하나하나를 외우기보다 **"지금 필요한 작업이 검사인지, 계산인지, 변환인지, 선별인지"** 먼저 구분하는 것이 더 중요하다는 생각이 들었다.

---

## 1. What — 무엇을 배웠는가?

### 핵심 개념

- **내장 함수(Built-in Function)**
  - 별도의 `import` 없이 Python에서 바로 사용할 수 있는 함수
  - `len()`, `sum()`, `round()`, `all()`, `any()`, `map()`, `filter()` 등이 있다.
- **표준 라이브러리(Standard Library)**
  - Python 설치 시 기본으로 함께 제공되는 모듈 집합
  - 사용할 때는 `import`가 필요하다.
  - `datetime`, `time`, `math`, `json`, `random`, `os`, `sys` 등이 있다.
- **`isinstance()`**
  - 값이 특정 자료형인지 검사한다.
- **`all()` / `any()`**
  - `all()`은 모든 요소가 참이면 `True`
  - `any()`는 하나라도 참이면 `True`
- **`len()` / `sum()` / `round()`**
  - 개수, 합계, 반올림처럼 자주 쓰는 계산을 간단히 처리한다.
- **`statistics.mean()` / `statistics.median()`**
  - 평균과 중앙값을 구한다.
  - 평균은 극단값의 영향을 크게 받고, 중앙값은 상대적으로 덜 받는다.
- **`map()` / `filter()`**
  - `map()`은 모든 요소에 같은 변환을 적용한다.
  - `filter()`는 조건을 만족하는 요소만 남긴다.
- **`enumerate()` / `zip()`**
  - 반복하면서 번호가 필요할 때 `enumerate()`
  - 여러 데이터의 같은 위치 값을 묶을 때 `zip()`
- **`sorted()` / `min()` / `max()`**
  - 정렬, 최솟값, 최댓값을 간단하게 처리한다.
- **대표 표준 라이브러리**
  - `datetime`: 날짜와 시간
  - `time`: 대기, 실행 시간 측정
  - `math`: 수학 기능
  - `json`: Python 객체와 JSON 변환
  - `random`: 난수와 무작위 선택
  - `os`: 파일·디렉토리·운영체제 기능
  - `sys`: Python 실행 환경 정보

### 핵심 코드

```python
values = [True, True, False]

print(all(values))  # False
print(any(values))  # True
```

```python
scores = [80, 90, 100]

average = sum(scores) / len(scores)
print(round(average, 2))
```

```python
import statistics

scores = [80, 90, 100]

print(statistics.mean(scores))
print(statistics.median(scores))
```

```python
prices = [1000, 2000, 3000]
discounted = list(map(lambda x: x * 0.9, prices))
```

```python
scores = [45, 80, 55, 90, 30]
passing_scores = list(filter(lambda x: x >= 60, scores))
```

### 오늘 수행한 학습

- `all()`과 `any()`가 각각 `and`, `or`와 비슷한 판단 구조를 가진다는 점을 연결해서 이해했다.
- `all([])`이 `True`, `any([])`가 `False`가 되는 빈 리스트의 특수한 동작을 확인했다.
- `len()`은 합계를 계산하는 함수가 아니라 문자열의 글자 수나 리스트·튜플의 **요소 개수**를 세는 함수라는 점을 다시 정리했다.
- `sum()`과 `len()`을 조합하면 평균을 직접 계산할 수 있다는 흐름을 확인했다.
- `mean()`과 `median()`의 차이를 배우면서 평균만으로 데이터를 대표하면 안 되는 경우가 있다는 것을 알게 되었다.
- `map()`과 `filter()`가 반복문을 짧게 표현할 수 있는 도구라는 점을 배웠다.
- `iterable`이란 리스트처럼 **요소를 하나씩 순서대로 꺼내볼 수 있는 객체**라는 개념을 다시 확인했다.
- 내장 함수와 달리 표준 라이브러리는 필요한 모듈을 먼저 `import`해야 한다는 차이를 정리했다.

## 2. Why — 왜 필요한가?

### 이 개념이 필요한 이유

- Python에는 자주 쓰는 기능이 이미 함수로 만들어져 있기 때문에 같은 로직을 매번 직접 구현할 필요가 없다.
- 코드가 짧아질 뿐 아니라, 함수 이름 자체가 작업의 목적을 보여주기 때문에 읽기도 쉬워진다.
- 조건문과 반복문을 직접 많이 작성하기 전에 `all()`, `any()`, `map()`, `filter()` 같은 도구가 있는지 먼저 확인하면 더 단순한 코드를 만들 수 있다.
- `datetime`, `json`, `os` 같은 표준 라이브러리를 활용하면 날짜 처리, 데이터 저장·전송, 파일 경로 처리처럼 실제 서비스에서 자주 필요한 기능을 처음부터 만들지 않아도 된다.

### 내 생각

> 지금까지는 무언가를 처리하려면 `if`, `for`, `while`을 직접 조합해서 코드를 만들어야 한다고 생각했다. 그런데 오늘 배우고 나니 Python에는 이미 자주 쓰는 작업이 함수로 많이 준비되어 있었다. 그래서 앞으로는 문제를 보면 바로 반복문부터 작성하기보다 **"Python에 이 작업을 대신해주는 함수가 있나?"**를 먼저 생각해보는 습관이 필요할 것 같다.

## 3. How — 어떻게 작동하는가?

### 내장 함수 사용 흐름

```text
데이터
↓
하고 싶은 작업 판단
↓
검사 / 계산 / 변환 / 선별 / 정렬
↓
알맞은 내장 함수 선택
↓
결과 확인
```

예를 들어:

```text
모든 조건이 맞는가?
→ all()

하나라도 맞는가?
→ any()

몇 개인가?
→ len()

모두 더하면 얼마인가?
→ sum()

모든 값을 바꾸고 싶은가?
→ map()

조건에 맞는 것만 남기고 싶은가?
→ filter()
```

### 표준 라이브러리 사용 흐름

```text
필요한 기능 확인
↓
모듈 import
↓
모듈.함수 또는 모듈.속성 사용
```

예:

```python
import datetime

now = datetime.datetime.now()
```

### `all()`과 `any()`를 내 말로 설명하기

> `all()`은 여러 조건을 한 묶음으로 보고 **전부 참인지** 확인하는 함수이고, `any()`는 **하나라도 참인지** 확인하는 함수다. 그래서 느낌상 `all()`은 여러 개의 `and`, `any()`는 여러 개의 `or`와 비슷하다.

### `iterable`을 내 말로 설명하기

> `iterable`은 함수 이름이 아니라, 리스트나 튜플처럼 안에 있는 값을 하나씩 꺼내서 반복할 수 있는 데이터다. `sum(iterable)`, `map(function, iterable)`처럼 함수 설명에서 iterable이라고 쓰여 있으면 **"여기에 리스트 같은 반복 가능한 데이터를 넣으라는 뜻"**으로 읽으면 된다.

## 4. 오늘의 문제 해결

### 문제 상황 1 — `all()`과 `any()`가 둘 다 True가 나오는 함수인가?

처음에는 두 함수 모두 결과가 `True`로 나오는 예제를 보고 역할이 비슷하게 느껴졌다.

```python
all([True, True])
any([False, True])
```

둘 다 결과는 `True`지만 이유가 다르다.

```text
all([True, True])
→ 전부 True
→ True

any([False, True])
→ 하나라도 True
→ True
```

### 해결 원리

> 결과값만 보지 말고 **판정 기준**을 봐야 한다. `all()`의 기준은 "전부", `any()`의 기준은 "하나라도"다.

### 문제 상황 2 — `all([])`은 왜 True인가?

빈 리스트에는 참인 값도 없는데 `all([])`이 `True`가 되는 것이 이상하게 느껴졌다.

```python
all([])  # True
any([])  # False
```

### 해결 원리

```text
all([])
→ False인 요소가 하나도 없음
→ True

any([])
→ True인 요소가 하나도 없음
→ False
```

실제로 입력값 검증에서 사용할 때는 빈 데이터 자체가 허용되는지도 따로 확인해야 한다.

```python
if user_inputs and all(user_inputs):
    print("검증 통과")
```

### 문제 상황 3 — `len()`은 언제 쓰는가?

반복문에서 조건에 맞는 데이터의 개수를 세는 문제를 보면서 `len()`과 카운트 변수의 역할이 섞였다.

- 이미 만들어진 리스트의 전체 요소 개수 → `len()`
- 반복하면서 특정 조건을 만족할 때마다 직접 개수를 누적 → `count += 1`

즉, `len()`은 **이미 존재하는 묶음의 전체 개수**를 셀 때 사용하는 함수다.

### 문제 상황 4 — `iterable`이 또 새로운 함수인가?

`sum(iterable)`, `map(function, iterable)` 같은 설명을 보면서 iterable이 별도의 함수나 문법처럼 느껴졌다.

### 해결 원리

> iterable은 함수가 아니라 **반복 가능한 데이터의 종류를 설명하는 용어**다. 리스트, 튜플, 문자열처럼 `for`문에서 하나씩 꺼낼 수 있는 값들이 대표적인 iterable이다.

## STAR 문제 해결 기록

### Situation — 상황

> 내장 함수를 배우면서 `all()`과 `any()`가 둘 다 `True`를 반환하는 예제가 나오고, `all([])`은 빈 리스트인데도 `True`가 되는 등 결과만 봐서는 함수의 차이가 잘 구분되지 않았다. 또한 함수 설명에서 계속 등장하는 `iterable`이 새로운 문법처럼 느껴졌다.

### Task — 해결 과제

> 함수 이름을 외우는 것이 아니라 각 함수가 어떤 기준으로 데이터를 판단하거나 처리하는지 구분하고, 함수 설명을 스스로 읽을 수 있어야 했다.

### Action — 실행한 행동

1. `all()`과 `any()`를 각각 `and`, `or`와 연결해서 판정 기준을 비교했다.
2. 빈 리스트에서는 "참이 있나?"와 "거짓이 있나?"라는 관점으로 `all([])`과 `any([])`의 결과를 다시 해석했다.
3. `len()`과 카운트 변수의 차이를 "전체 요소 개수"와 "조건을 만족한 횟수 누적"으로 나누어 정리했다.
4. `iterable`을 실제 리스트와 연결해 `for`문에서 하나씩 꺼낼 수 있는 데이터라는 의미로 다시 정의했다.
5. 내장 함수들을 `검사 / 계산 / 변환 / 선별 / 정렬`이라는 작업 목적별로 묶어보았다.

### Result — 결과
