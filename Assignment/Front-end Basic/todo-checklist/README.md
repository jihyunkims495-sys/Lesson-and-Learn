# Todo 체크리스트

HTML·CSS·JavaScript의 기본 문법과 DOM 조작을 활용한 Todo 체크리스트입니다. 처음에는 할 일·진행 중·완료로 나누어진 칸반 보드로 제작하려 했지만, 구현에 어려움을 겪어 방향성을 피봇하고 지금까지 배운 내용을 직접 설명할 수 있도록 체크박스 형태의 목록으로 단순화했습니다.

## 화면 구성

- `header`: Todo Board 제목과 사용 방법
- `main`: 일정 입력 폼과 Todo 체크리스트
- `footer`: 새로고침 시 데이터가 초기화된다는 안내

# style.css 파일 구성
전체 글꼴은 `sans-serif`, 배경은 `white`, 기본 글자색은 `black`입니다. 버튼과 강조 색상에는 `orange`, 완료 전 일정 제목에는 `blue`, 완료한 일정에는 `grey`와 취소선을 적용했습니다.

## 기능

| 기능 | 동작 |
| --- | --- |
| 일정 추가 | 제목과 내용을 입력하고 `추가` 버튼을 누르면 체크리스트에 일정이 생깁니다. |
| 완료 표시 | 체크박스를 선택하면 `done` 클래스가 적용되어 글자가 회색과 취소선으로 표시됩니다. 체크를 해제하면 원래 상태로 돌아갑니다. |
| 일정 수정 | `수정` 버튼을 누르면 기존 내용이 입력창에 표시되며, 수정 후 `저장`할 수 있습니다. |
| 일정 삭제 | `삭제` 버튼을 누르면 해당 일정이 목록에서 사라집니다. |
| 일정 조회 | `전체 / 할 일 / 완료` 버튼으로 원하는 일정만 볼 수 있습니다. |

## 폴더 구조

```text
todo-checklist/
├── index.html      # 입력 폼, 조회 버튼, 체크리스트
├── css/
│   └── style.css   # 화면 배치, 색상, 체크 완료 표시 지침 정리
├── js/
│   └── todo.js     # 일정 추가·수정·삭제·조회 기능 넣기
└── README.md
```

## 실행 방법

1. `index.html` 파일을 Chrome이나 Edge 브라우저로 엽니다.
2. 별도의 설치나 서버 실행은 필요하지 않습니다.
3. 브라우저를 새로고침하면 입력한 일정은 초기화됩니다.

## 기능 확인 순서

- [ ] 제목을 비운 채 `추가` 버튼을 누르면 HTML `required` 입력 안내가 표시된다.
- [ ] 제목과 내용을 입력하면 체크리스트에 일정이 추가된다.
- [ ] 체크박스를 선택하면 일정이 완료 표시된다.
- [ ] `할 일`과 `완료` 버튼을 누르면 해당 일정만 보인다.
- [ ] `수정` 버튼을 누르면 기존 내용이 입력창에 표시되고 저장할 수 있다.
- [ ] `삭제` 버튼을 누르면 일정이 목록에서 사라진다.

## 교안 내용과 구현 연결

| 구현 내용 | 사용한 학습 내용 | 코드에서 확인할 부분 |
| --- | --- | --- |
| 화면 구조 | HTML의 `header`, `main`, `section`, `nav`, `footer` 시맨틱 태그 | `index.html` 전체 구조 |
| 일정 입력 | `form`, `label`, `input`, `textarea`, `button` | `index.html`의 일정 추가 영역 |
| 완료 체크 | HTML의 `input type="checkbox"` | `saveTodo()`에서 만드는 체크박스 |
| 기본 배치 | CSS 박스 모델과 Flexbox | `style.css`의 `.panel`, `.todo-item`, `.todo-actions` |
| 색상과 동작 표시 | `:hover`, `:focus`, 클래스 선택자 | 버튼 hover, 입력 focus, `.todo-item.done` |
| HTML 요소 찾기 | `getElementById`, `querySelector` | `todo.js`의 DOM 요소 선택 부분 |
| 새 일정 만들기 | `createElement`, `innerHTML`, `textContent`, `append` | `saveTodo()` 함수의 일정 생성 부분 |
| 완료 상태 바꾸기 | `classList.toggle`, `checked` | `checkTodo()` 함수 |
| 추가·수정 구분 | 변수, 함수, `if` 조건문 | `editingItem`, `saveTodo()` |
| 목록 조회 | `data-*`, `dataset`, CSS 속성 선택자 | `filterTodos()`와 `style.css`의 `data-filter` 선택자 |
| 일정 삭제 | DOM 요소의 `remove()` | 삭제 버튼의 `onclick` 함수 |
| JavaScript 연결 | `script` 태그의 `src`와 `defer` | `index.html` 하단의 script 태그 |

## 체크리스트 형태로 바꾼 이유

- 수업에서 배운 체크박스와 DOM 조작을 바로 확인할 수 있습니다.
- 배열에 데이터를 저장하고 화면 전체를 다시 그리는 복잡한 방식 대신, 입력할 때 목록 요소 하나만 추가합니다.
- `let`, `const`, 함수, 조건문, DOM 선택과 생성처럼 배운 기본 내용으로 기능을 구성했습니다.

## JavaScript 단순화

처음 만든 칸반 버전에는 일정 배열, 일정별 ID, 상태값, 반복 렌더링 코드가 포함되어 있었습니다. 최종 버전에서는 해당 코드를 제거하고 새로운 일정을 화면에 직접 추가하도록 변경했습니다.

- `saveTodo()` — 새로운 일정 추가 및 수정 내용 저장
- `checkTodo()` — 체크박스 완료 상태 변경
- `editTodo()` — 기존 제목과 내용을 입력 폼으로 가져오기
- `deleteTodo()` — 선택한 일정 삭제
- `resetForm()` — 입력 폼을 일정 추가 상태로 초기화
- `filterTodos()` — 전체·할 일·완료 목록 조회

일정 조회는 JavaScript 반복문을 넣어 목록을 다시 그리지 않습니다. `filterTodos()`가 목록의 `data-filter` 값만 변경하고, CSS 속성 선택자가 조건에 맞지 않는 일정을 숨깁니다.

## 눈물의 골짜기

파이썬 보다 눈에 보이는 html을 구성하고 javascript를 넣고 구현한다는 건 알지만, 이를 이해하고 -> 구조를 짜고 -> 실패를 거듭하고 -> 다시 실행해보는데 있어 아직 완전히 이해하지는 못했습니다. 손그림으로 figma로 ppt로 구현하고 싶은 부분과 표현하고 싶은 부분을 그리고 또 실행해봤지만 번번히 실패하며 다시 제자리로 돌아왔습니다. 최대한 이해한 부분을 구현해보려 했지만, 제대로 된 리스트 인지 스스로 평가하지는 못합니다. 이 부분이 가장 아쉽게 남습니다.
